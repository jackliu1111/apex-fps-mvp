# interval-v1 功能与性能验收（2026-09-16）

实现与接口说明见 [interval-v1.md](interval-v1.md)，含内嵌截图的离线报告见 [interval-v1-validation.html](interval-v1-validation.html)。本轮仅修改 TypeScript 源码，没有重新打包或发布。

## 功能验证

- 类型检查：`bun run check`。单元测试覆盖探测端点、不变/上升/异常、相邻异常合并、基线断点、单帧误读、边界归属、候选缓冲/末尾补足、真实 CFR/VFR 时间戳与像素、单帧视频、取消和工具失败。最终 36 项单元测试通过，零失败。
- 10 项完整流程验证全部通过，覆盖批量分析、三段窗口候选、浏览器 H.264/AAC 预览与 Range、精确导出帧数、文件变更拒绝、并发拒绝、取消和重启；新增旧格式任务加载/预览/导出并确认保存文件字节未改写。
- 浏览器目视检查：参数页仅保留合并/缓冲，显示固定策略；新结果显示高亮窗口数，虚线按端点线性连接；增长窗口导航和范围/净变化详情正常；旧结果仍显示增长事件。

## 完整分析实测

平台：Apple M4、24 GiB 内存、macOS arm64，Bun 1.3.12 源码运行，FFmpeg/ffprobe 7.1.1；没有编译验证或 Windows 运行验证。源项目要求发布构建使用 Bun 1.3.13+，本次没有更改或升级运行时。
同一机器、媒体工具和文件，软件解码；参数均为 gap=5、before=1、after=2。旧方案为冻结的全程 30 FPS 代码，新方案固定 5 秒/10 FPS。每组有效对照均按旧→新→旧→新排序，完整录像首对复用已完成的最终版本运行，随后补做第二对；所有预跑和原始标签也保留在记录中。没有并发启动分析任务，不清空系统文件缓存、不控制系统后台负载；期间有少量代码/浏览器检查，因此按两次实测值报告，不作为统计显著性结论。
计时范围为完整 `analyzeSource`：文件 SHA-256、ffprobe、供帧、识别、候选生成及结束文件检查；不含 UI 启动、结果 JSON 写盘和视频导出。RSS 是约每 200 ms 采样主进程与后代进程 RSS 的和，并非独占物理内存的精确峰值。HUD 时间包含在分析阶段内，不能把各列相加。

- stable：完整分析耗时变化 +11.3%；读取帧数减少 86.5%，RGB 管道减少 85.1%。
- anomaly：完整分析耗时变化 +29.6%；读取帧数减少 70.2%，RGB 管道减少 74.7%。

减少帧数和管道量没有带来墙钟提速。数据表明稀疏阶段开销较大、完整录像补查占比达 84.9%；随机跳转、反复启动 FFmpeg 和关键帧前向解码是可能的成本来源，本轮未将这些成本单独隔离计时。以上表格只使用最终实现的数据，修正过程中的预跑结果不参与结论。

## 差异画面目视抽查

完整录像 64.5–64.7 秒：画面可见 549→560，属于新候选未覆盖的真实可见计数增长。补查在 64.604 秒读到 560，但 64.704 秒未知；随后 64.804/64.904 秒的 560 只能重新建立基线，因此按未知断点规则未生成事件。60–65 秒窗口未高亮，前一候选在 62 秒结束。此次保守确认确实损失了这一处覆盖。

完整录像 343.8–344.167 秒，以及稳定段 21.4–21.7、36.1–36.4、47.9–48.2 秒的抽查画面均显示 160；旧方案对应输出 160→180，与所抽查画面不符，支持这些差异是旧识别误报的判断。抽查不代表已逐帧排除所有短暂变化。

新方案新增确认的 49.604 秒附近可见 516→549，325.504/325.804 秒附近可见 117→149→160；抽查画面支持这些增长，并被对应完整基础窗口覆盖。

以上是对指定差异附近画面的目视抽查，没有制作全片人工真值；旧增长位置覆盖率不能直接当作召回率。原始窗口、逐帧读数和截图全部保留，便于进一步核查。
