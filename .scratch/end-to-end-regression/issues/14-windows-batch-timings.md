# 14 · Windows 批量导入分段耗时基线

**What to build:** 在报告问题的平台上对照单份和批量导入，定位耗时所在阶段。

**设计分支**　I1、I2、I4 · [端到端回归测试设计](../../../docs/design/end-to-end-regression.md)

**Blocked by:** None (can start immediately)

**执行条件**　实机验收。Windows Edge、授权使用的录像、原存储位置。

**Status:** completed

## 验收标准

- [x] 同机同素材分别进行单份和批量导入，记录版本、存储位置类型和导入顺序。
- [x] 逐文件记录从选入到出现行、读取轨道、等待队列、分析启动及首个可复核片段的时间。无候选或观测缺失的阶段按实际标注。
- [x] 结合队列与界面解释任务未启动、排队和读取慢的区别；即使未复现，也提交原始观测和环境信息，本轮以建立基线验收。


## Windows 实机记录 · 2026-11-28

Windows 11 专业版 build 26200，原生 Edge 158.0.4370.45，独立 headless 配置。服务来自本地集成工作区（应用代码与 `c6b83c0` 相同），经 SSH 回环端口提供静态页面。Edge 的文件输入框在 Windows 上直接打开原文件。E: 为 Samsung SSD 980 1TB，固定 NVMe，NTFS。两份录像均来自同一 OBS 原输出目录。A 为 2026-11-28 16-07-56.mkv（313392110 字节，158.57 秒），B 为 2026-11-27 21-14-34.mkv（475744848 字节，361.17 秒）。

每轮依次单选 A、单选 B、批选 A+B，每次新开页面，无时序控制。零点为文件输入框 change，MutationObserver 采集录像行和状态徽章变化，同步读取对应队列任务状态和稳定片段；表中为第一次观察到该事件的累计毫秒。两轮共六次真实导入。
