# 09 · 第二段写入失败后的取消与恢复

**What to build:** 在同一批次的第一段已关闭、第二段写入中失权时，分别验证取消和恢复。

**设计分支**　E3、E4 · [端到端回归测试设计](../../../docs/design/end-to-end-regression.md)

**Blocked by:** None (can start immediately)

**执行条件**　至少三段，能向写入中的第二段注入权限错误，支持目录重选、残件清理失败和读回。

**Status:** completed

## 验收标准

- [x] 从产品页提交后修改当前选片。第一段成功、第二段开始写入后注入错误，面板提示重选目录，已保存数为 1，第一段可读。
- [x] 取消分支保留第一段，停止余项；恢复分支只写余项，第一段不重复写、内容不变，最终目录与原批次快照逐文件一致。
- [x] 注入清理失败时，面板给出实际残件位置。记录错误发生时点，区分段间撤权和写入中失权。

## 本地验证

基线 `c6b83c0`。macOS Chrome，临时 OPFS，4 秒 12 fps 源 B 的烧录帧号。使用本票 serve.py 的端口 18909，运行 `REVIEW_URL=http://127.0.0.1:18909 node model_web_ui/browser.prototype/tests/verify-partial-export.cjs`（本机 playwright-core 和 Chrome），取消、恢复各用新页面，均通过。批次固定范围 0–0.5、1–1.75、2–3 秒。

两次均在第一段真实 close 成功、第二段 writer.write 已写入块后暂停，返回复核取消勾选第三段，然后注入 NotAllowedError。面板提示重选、完成 1/3。取消后原目录仅剩第一段。恢复场景另注入清理失败，面板准确列出实际残件 original/文件名，新目录仅写第二和第三段。两次第一段 SHA-256 保持一致，首次目录的关闭记录始终只有第一段。恢复后完成 3/3，逐个从各自目录读回请求片段；0.25 秒处依次解码到 B 的第 3、15、27 帧，实际片长 0.48、0.74、0.98 秒。两个页面均无未处理异常。
