# Apex 模型服务方案原型

状态：可丢弃的决策原型；用户已确认第一版处理本地录屏，部署方案仍待用户评估。没有接入正式服务、模型运行或真实视频导出。

## 要回答的问题

对本地录屏离线枪声检测，怎样同时减少环境安装和处理等待？Web 界面、推理位置和打包形式分别选择，避免把网页界面等同于视频上传。

双击 [单文件原型](model-service.prototype.html) 即可使用，无依赖、联网、服务或持久化要求。页面含四条部署路径、耗时计算、模拟任务状态和真实历史枪声候选合并。

## 当前建议及依据

建议先复用 `typescript/src/main.ts`、`server.ts` 的双击启动本地网页流程，增加随包推理进程，复用 FFmpeg 媒体工具与导出。模型进程启动时加载一次权重，任务复用同一个模型；界面异步提交任务并查看阶段进度。Python 是内部实现依赖，通过包内运行时解决，用户无需执行脚本或安装解释器。

桌面外壳可以复用同一个引擎；是否选择 Tauri 等框架尚未决定。云端只传音频可降低上传量，但客户端仍需抽音频和视频导出能力。纯浏览器推理需要另做模型转换、算子与前处理兼容性、一致性和真实设备速度验证。

当前证据是 2026-09-29 的已有运行结果，2026-09-30 本次只读取核验，没有重跑模型：

- `/Users/jackliu/game/apex-voice-detect/runs/apex_full_beats_20260929/summary.json`：BEATs CPU，4 threads / batch 1，1293.9306875 秒音频；258 个 10 秒窗口 / 5 秒步长；推理循环 54.707177792 秒，RTF 0.0422798364，脚本总耗时 58.480819125 秒。输入音频提前抽取；不含整条视频到成片链路。不是 ATST-F 测速。
- 同目录 `source_manifest.json`：原录像 16,823,282,156 字节。按 20 Mbps 上行、十进制单位理想计算，上传约 6729.3 秒（112.16 分钟）。16 kHz mono PCM16 全片音频约 41.4 MB，上传约 16.6 秒；实际网络和媒体处理另测。
- 同目录 `events.json`：内嵌 Gunshot / Machine gun 两类在 0.1、0.2、0.5 阈值的 397 条历史候选。0.2 阈值有 113 条；候选未核验 Apex 精度。不是开枪次数，也不能区分本人、队友和远处枪声。
- 原型中的抽取、云端 RTF、排队、启动和导出耗时均为可编辑假设。串行估算不含后处理、人工复核、网络波动、模型首次下载等费用；不构成完整性能承诺。

后处理顺序为跨类别时间并集 → 按事件间隔聚类 → 添加前后留白 → 裁剪到源时长 → 合并重叠裁剪范围。阈值、间隔和留白变化只重算候选，清空旧选择；正式实现应缓存原始帧级分数。原型使用历史已解码的三个阈值，不支持任意阈值。

默认阈值 0.2、合并间隔 4 秒、前 5 / 后 8 秒：113 条候选 → 105 段并集 → 35 个事件簇 → 19 段候选片段，共 578.6 秒。留白形成的最终合并效果可能盖过事件间隔的小幅调整。这些是产品参数示例，尚未验证最优选片效果。

## 本次检查与边界

完成内联脚本语法检查和浏览器交互检查：本地路径推进到模拟完成、调参不增加推理次数且清空选择、取消未完成推理后重新开始、未完成推理或没有勾选时拒绝导出。没有新增测试套件。所有导出均为状态演示，无视频产物。

真实服务下一步需分阶段计时冷/暖启动、音频抽取、模型推理、后处理、预览和成片导出，并核验一条真实录屏端到端。至少覆盖代表性 1080p / 4K 录像和目标用户设备。识别质量、音频时间到视频 PTS 映射及感知音画延迟、快速复制与重编码切点需要分别验证。

待确认：主要用户操作系统及硬件、可接受等待时间、目标高光是否只用枪声候选即可。
