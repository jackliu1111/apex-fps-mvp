# 分析与复核并行交互方案

日期：2026-10-27。状态：主要产品规则已确认，作为后续实现依据；真实媒体播放、任务调度和保存恢复尚需实现与验证。提前浏览、连续播放和局部放大以不显著增加等待为验收条件。

用户希望减少等待与操作复杂度：分析持续处理后续时间线，复核消费前面已经产生的结果。分析页和复核页承载不同任务，切换页面不会自动暂停分析。分析应尽量从头到尾只读取一次原录像，避免不同功能重复扫描相同媒体。核心决策见 [ADR 0003](../adr/0003-independent-analysis-and-review.md)，术语沿用 [CONTEXT.md](../../CONTEXT.md)。

## 已确认的交互方向

- 分析和复核可以并行，不要求整份录像分析完成后才开始复核。
- 分析页管理素材与分析进度，复核页管理当前选片活动；页面切换不等于停止或启动另一任务。
- 用户查看前面的稳定候选时，分析可以继续处理后面的时间线。
- 界面需要按任务组织操作，避免把会互相争抢资源的重操作集中在一个工作区；仅隐藏按钮或切换页面不能代替任务调度。
- 单次连续读取只约束分析链路。复核和导出允许按需读取原片，不要求首次扫描时生成全部视频预览。
- 复核和导出允许利用附近关键帧简化处理，实际范围可以与用户请求范围存在差异。界面沿用请求范围和实际范围的区别，不承诺逐帧精确切点。
- 用户不需要选择或确认音轨。音频如何用于检测由系统处理，不把媒体内部结构变成开始分析前的必填项。此决定替代旧流程中每份录像必须显式确认游戏音轨的要求。
- 复核以完整原片和全片时间线为中心，方便快速拖动查看与调整范围。视频需要异步或渐进加载，不以整文件加载或整文件转码完成作为开始观看的前提。
- 新稳定候选自动追加并提示数量，不要求手动刷新或接收，不改变当前播放位置和用户编辑。
- 默认允许提前浏览未分析区域、连续播放原片，并提供全片概览与局部放大。用户接受这些默认的前提是不显著增加等待；当前仅确定交互方向，真实媒体性能尚未验收。
- 人工修改和明确排除持续保留，调参不能覆盖已经做过的操作，只有用户主动重置时才清除。自动建议与人工复核决定分别维护，见 [ADR 0004](../adr/0004-preserve-review-decisions.md)。
- 与原排除范围重叠的新候选默认不勾选，作为补充建议；完全重复的已排除候选不再出现。原排除决定继续保留，不因新候选扩展而自动扩大排除范围。
- 允许提前提交范围确定的选片导出，提交时固定该批范围，后续修改用于下一批。已提交批次与当前编辑内容分别维护，见 [ADR 0005](../adr/0005-fixed-export-batches-and-saved-review.md)。
- 自动保存选片和复核位置，优先保证刷新后不丢失人工操作。分析断点续算后置，恢复选片不等于恢复运行中的分析。

## 当前实现与目标的差距

当前浏览器原型每份录像只建立一个持续的音频解码迭代器，以约 5 秒的音频块为单位生成单声道数据，相邻推理窗口复用该块；推理时最多预读下一窗口。见 [stream-audio.js](../../model_web_ui/browser.prototype/stream-audio.js) 和 [分析入口](../../model_web_ui/browser.prototype/app.js)。

这只证明应用层使用一条持续解码流水线。导入与分析初始化还会查询轨道、起点和时长；容器解析器及操作系统如何读取数据，不能由迭代器数量推断。验收时需分别记录分析扫描、初始化读取、预览读取与导出读取，不能把“一个迭代器”写成“每个物理字节只读取一次”。

预览和导出仍分别调用转换流程，按范围读取原视频及所选音轨，再生成 WebM。分析已产生候选，不代表相应视频预览已经生成。相同预览与导出产物目前也未复用。

当前播放器加载的是转换完成后的片段 Blob，时间线只覆盖该片段。目标要求整文件可定位、按当前位置准备视频，需替换这条播放路径；仅扩大候选列表或换一条进度条不能获得整文件渐进播放能力。真实容器的定位与分段播放效果仍需验证。

现有代码仍要求显式选择音轨，自动准备分析音源尚未实现。移除界面确认步骤需要补齐系统内部的音源处理，不能仅隐藏控件而保留原有的阻塞条件。

现有浏览器原型重算候选会清空移除记录并替换候选列表，自动候选键取自事件起点。此行为不满足人工决定持久保留的新规则；起点改变或候选拆分、合并时，不能把同一内容当成没有人工处理过的新结果。

## 一条分析流水线供应多种结果

建议由同一条分析流水线提供渐进结果和后续复用数据，而不为每种产物重新扫描原片：

```text
原录像 → 一条持续读取与音频提取流水线
                         ├→ 解码与推理 → 分数 → 稳定候选 → 复核任务
                         └→ 带时间信息的压缩音频缓存 → 后续重新分析

原录像 → 按播放位置读取附近视频 → 整文件复核播放器
原录像 → 按选片范围读取视频 → 导出
已有且范围与设置一致的成片 → 复用，避免重复转换
```

已有分数支持候选重算，无需重新推理。音频缓存可支持需要重新推理的操作；压缩包应在解码前分发，不能把解码后的波形直接当作原始 AAC 包保存。缓存完成、校验和失效条件沿用[音频供给研究](../audio-supply-research.md#实现边界)。缓存分支尚未实现，不将其收益算作现有能力。

音频缓存不能提供复核画面。已选择按需读取原片的路线，分析扫描不承担为整片生成视频预览的前置职责；预览与导出的读取另行记录。可复用的预览必须有容量边界，不能默认把已读过的视频无限留在内存。

## 两页的对象和职责

两个页面分别围绕任务队列和整份录像组织交互。以下是目标行为，不代表当前原型已实现。

| 页面 | 主要对象 | 用户主要操作 | 主区域不承载的操作 |
| --- | --- | --- | --- |
| 分析页 | 多份录像构成的任务队列 | 导入、移出待处理队列或停止指定分析、查看结果是否可用、进入复核 | 音轨确认表单、播放视频、逐段裁边、执行批量导出 |
| 复核页 | 当前原录像的完整时间线与用户选片 | 全片定位播放、点击候选跳转、保留或排除、调整边界、提交选片 | 配置其他录像的分析任务、展示完整模型与性能日志 |

页面共享同一份素材、分析进度、候选与用户选片。分析中的录像和用户正在看的录像分别记录，两个页面不各自维护一份候选副本。

## 分析页

页面顶部提供导入入口，主体是录像队列。每行展示名称、时长、状态、已处理到的录像时间与稳定候选数。导入后自动准备并加入分析队列，不再经过音轨确认或额外全局开始步骤。模型、5/5/5 默认规则与诊断信息放入高级设置，不作为每次开始前的必填表单。

按录像状态提供主要动作：

| 录像状态 | 主要动作 | 结果与边界 |
| --- | --- | --- |
| 正在准备 | 展示准备状态 | 系统读取必要媒体信息并处理分析音源；选择其他文件不必等待 |
| 排队中 | 查看排队状态 | 可以移出尚未开始的队列 |
| 分析中且暂无稳定候选 | 查看已处理时间、浏览原片 | 媒体可定位后允许提前浏览，不宣称视频已缓存 |
| 分析中且有稳定候选 | 复核已有 N 段 | 进入复核，分析继续 |
| 分析完成 | 开始或继续复核 | 正常结束后才发布最后的稳定范围 |
| 失败或已停止 | 查看原因或重试；已有候选可复核 | 保留稳定候选与人工修改，不承诺从中断点续算 |

单份录像准备未完成不阻塞其他已就绪录像；一份失败也不应抹掉其他结果。后台开始下一份录像时只更新队列，不替用户切换复核对象。停止按钮只作用于指定分析，不取消播放器中的预览。

用户只面对“导入、自动分析、进入复核”这条主流程。音轨的数量、编号、编码等信息不出现在必经流程。确实无法取得可分析声音时，在该录像行给出具体原因，不伪装成“未发现枪声”。停止后的重试不应在界面上冒充断点续跑。

内部音源策略需要针对单音轨与多音轨录像验证，同时遵守分析单次扫描约束；不能把后台逐条重新扫描整个原片当作自动化方案。默认选择第一条、混合所有音轨或自动试选，目前都没有确定。用于检测的音频与预览、导出保留的声音是不同问题，不能因隐藏选轨界面而悄悄改变输出声音。

## 整文件复核页

一次聚焦一份原录像。页头保留返回分析页、当前文件，以及简短分析状态，例如“已分析至 18:30 / 44:00，后续仍在分析”；切换录像后恢复该录像的观看位置与选片状态。

主区域由播放器和完整录像时间线构成，候选列表作为辅助导航。时间线覆盖原片从开始到结束的全部时长，候选显示为其上的范围标记。点击候选时，在同一原片播放器中跳到对应位置并选中该范围，不切换成独立片段播放器。

沿用默认预选全部普通候选的规则，重叠补充建议例外。勾选表示加入导出选择，不表示已经看过。默认连续播放原片，经过候选终点不自动跳过中间内容；保留或排除只作用于选片，不自动切换播放位置。“下一候选”保留为主动跳转操作。用户仍可通过列表快速跳转和批量修改选择，不强制每段人工确认后才能导出，也不把自动稳定或打开播放器记为人工确认。

新稳定候选直接追加到列表，并在原片时间线的对应位置增加标记，显示新增数量；当前播放位置、选中范围、时间线缩放、滚动位置和输入内容保持不动。仍可能延长的候选与稳定候选分开表达，可显示“后续片段正在补全”。后台结果不自动改写人工选片范围。

### 视频异步加载与跳转

以下为实现已确认体验目标的建议行为；具体播放后端尚未选定。

1. 取得必要时长与定位信息后，先建立完整时间线；不把全片视频解码、复制或转码作为显示时间线的前置条件。
2. 视频围绕当前播放位置按需读取、解码或准备可播放数据，连续播放时有限预取后续内容。回到已准备范围时优先复用有界缓存。
3. 拖动时立即更新目标时间，默认松手后优先准备最后目标附近的画面，避免为每个中间位置启动媒体转换。已就绪的近似画面可以复用；需要等待时，只在播放器提示“正在准备该位置”，时间线和选片操作仍可使用。
4. 快速连续跳转以最后一次目标为准，过期请求不能更新当前画面或覆盖加载状态。优先响应新的位置，取消或忽略已无用的准备工作。
5. 跳转取数允许从附近可解码关键帧开始；定位目标、实际显示位置与用户选片边界分别维护，不因取数起点改变而悄悄移动选片边界。
6. “已分析到哪里”和“当前位置视频是否就绪”分别表达。分析仍按其顺序推进，不跟随播放头跳转；尚未分析不能被描述成已经确认无交火。

默认允许用户跳到尚未分析的区域，例如分析到 10 分钟时查看 35 分钟的画面；这里只缺少检测结果，不代表视频必须等分析才能读取。这个默认以按需读取为边界，不为允许提前浏览而预先处理全部未分析区域。

按需播放的读取允许回访原片，不受分析链路单次扫描约束；但其资源竞争仍需调度，不能将异步调用等同于没有读取或解码成本。所有格式都能即时跳转不是已有能力。

### 选片与范围调整

选片是原片时间线上的范围，播放器在范围外继续浏览不丢失该选片。默认保留全片概览，并在选中范围时提供局部放大的范围条。概览与放大只使用已知时长、候选和选片坐标，不以生成全片缩略图、波形或额外视频缓存为前置条件。

拖动选片边界先更新请求范围，不为每个拖动位置重新生成整段成片；画面定位与最终导出各自消费该范围。允许按关键帧处理，但不把未经验证的实际范围显示为精确执行结果。

离开复核页暂停播放器并记住位置，后台分析继续；再次进入恢复该录像、观看位置和选中范围，默认保持暂停，由用户继续播放。候选列表到末尾而分析尚未结束时，显示“当前候选已到末尾，后续仍在分析”，全片播放器仍保留其浏览能力，不显示整份录像工作完成。

页尾汇总已选片段数与总时长，并提供导出入口。提交后形成独立批次，用户可以继续复核；导出执行状态在独立任务区域查看，不与选片表单共用一个忙碌锁。每段独立导出、按原录像时间排列的规则保留，具体任务调度根据实际资源与性能验证确定。

## 调参与人工复核决定

用户已确认：人工修改和明确排除的片段都要保留，调参不能覆盖用户已经做过的操作，只有主动重置时才清除。

自动候选表达系统当前建议；人工复核决定表达用户已经作出的选择，二者不是一份可整体替换的列表。默认勾选不构成人工保留，显式保留、排除、裁边和手动新增都属于需要保留的人工操作。相同原录像内的候选版本变化不能使这些决定丢失；不能把它们自动套用到另一份录像。

直接落实为以下规则：

- 人工调整后的起止范围原样保留；新参数检不出该片段，也不自动删除或取消选择。
- 明确排除继续有效；自动候选的起点、数量或分组改变，不能使排除内容重新被默认选入导出。
- 新候选持续追加和参数重算均不能覆盖当前编辑，也不能重复添加一份与人工选片相同的已选内容。
- 参数重算仍消费已有预测分数，不因为保存人工决定而重新扫描原片或重新推理。
- “调整筛选”与“重置人工选片”分开提供。主动重置应明确影响的录像及将清除的修改和排除记录，不隐藏在调参、重试或页面切换中。
- 用户主动修改某项决定属于新的人工操作；系统不能把自动更新伪装成这种主动修改。

### 新结果与人工决定重叠

候选边界移动、拆分或合并时，仅凭候选 ID 或起点不能判断用户原有意图。需要保留与原录像及相应范围的关系；具体关联方式是内部实现，不要求用户理解版本或 ID。

已裁好的选片保持独立。例如用户将 10:00–10:30 裁为 10:04–10:22，新参数生成 09:58–10:35 或拆成两段，都不能改掉 10:04–10:22，也不能自动重复选入这段内容。

用户已确认排除后的重叠处理：原排除决定保留，重叠的新候选默认不勾选，作为补充建议；完全重复的已排除候选不再出现。

| 已有人为决定 | 调参后的自动结果 | 行为 |
| --- | --- | --- |
| 排除 20:00–20:20 | 再次产生 20:00–20:20 | 不再加入候选或补充建议，原排除记录保留 |
| 排除 20:00–20:20 | 产生 19:55–20:35 | 新范围作为未勾选补充建议，标示与排除范围重叠；原排除不扩大、不失效 |
| 保留 30:00–30:15，排除 30:20–30:35 | 合并成 29:55–30:40 | 原人工选片和排除都保留；新大段默认不勾选，用户可主动处理 |

按用户明确处理的原录像范围保存决定，不使用未经验证的“同一次交火”语义扩大决定范围。补充建议不会自动加入导出，也不通过弹窗要求用户立即处理。完全重复结果的隐藏不等于删除原排除决定；用户主动重置后才重新按照当前自动结果建立选择。

## 沿用的候选与输出规则

- 默认事件间隔不超过 5 秒合组，前后各留 5 秒；持续交火不强制拆分，留白重叠不再次合并。
- 普通候选默认预选，补充建议默认不选；范围稳定不等于人工已看过，也不等于已确认精彩。
- 每个选片分别导出，按原录像时间排列，不默认拼接成一个集锦。
- 请求范围与实际导出范围分别表达，允许关键帧和包边界造成实际范围偏移。
- 界面使用枪声候选或候选片段，不把模型输出表述为本人开枪、命中、击杀或已确认高光。

## 有条件采用的交互默认

提前浏览未分析区域、连续播放原片、全片概览与局部放大采用默认方案，条件是不显著增加等待。这些功能不需要用户在首次使用时配置。

### 默认不增加的前置工作

- 进入复核页不先完整读取、复制、解码或转码原录像。
- 不预先转换全部候选，不为尚未查看的位置批量生成缩略图或完整波形。
- 时间线缩放、范围编辑和候选追加先更新界面状态，不触发重复分析或整段视频转换。
- 视频只围绕当前请求做有界准备，旧定位请求不得持续积压，也不得覆盖新画面。
- 页面切换、概览缩放和候选追加不自动暂停分析；调度优化不能偷偷改回分析与复核分阶段执行。

### 性能验收

使用同一素材、存储位置和环境，对照当前片段预览与整文件按需播放；记录从进入复核到首个画面、定位到目标首画面、拖动和编辑响应、连续播放中断，以及复核同时进行时完整分析耗时的变化。以重复结果和正常波动判断回退，不凭单轮或界面示意宣称“不增加等待”。首次与重复定位需要分开记录。

概览和局部放大可先验证是否只更新已有坐标。提前浏览与连续播放确实需要媒体读取，必须在真实录像上验证其等待与资源竞争。如果出现明显回退，先收紧可选预取、取消无效请求、复用已就绪数据并检查播放路径，不增加整片预处理步骤来掩盖等待。必要的行为取舍再回到用户讨论。

当前交互示意的准备计时是模拟，不代表真实首帧或跳转性能；现有分析耗时也不能证明新播放路径已通过验收。

## 导出与自动保存

### 提前提交并固定导出批次

允许在整份录像分析结束前提交已选且范围确定的片段，包括稳定自动候选和用户明确指定的手动范围；仍在补全的自动候选不进入该批次。沿用默认预选可以导出、无需强制逐段人工确认的规则。

提交时固定本批的片段、请求范围、原录像、声音及输出设置，包括仍在队列中的批次。后台根据资源安排执行，不要求立即与其他重任务同时运行；界面区分已提交、排队和实际执行。用户继续复核和修改当前选片，后续修改用于下一次提交；后续新候选、调参、排除或重置人工选片也不能悄悄改变已提交批次。取消本批导出是独立操作。

例如本批提交 01:20–01:40，之后用户改为 01:23–01:37，本批仍按前一个请求范围导出，工作区显示后续修改尚未导出。每段独立输出、按原片时间排序、关键帧实际范围可能偏移的既有规则保持不变。

导出逐段交付结果，失败或取消保留已完成片段，并明确其他片段的状态。刷新后恢复批次记录，不据此假设任务仍在运行、可以续导或内存中的成片仍然存在；实际中断和缺失产物应如实显示。重复导出不覆盖已有文件。

### 自动保存选片工作

自动保存人工选片范围、明确保留与排除决定、补充建议处理状态、复核位置和已提交批次记录。刷新或重新打开后恢复这些工作，必要时重新关联或授权原录像；不要求用户额外点击保存才能保护修改。恢复后先展示选片和位置，不能要求先重新分析才能找回人工操作。

短时间连续编辑可以合并写入，但界面只有在对应修改实际保存成功后才显示“已保存”。旧保存响应不能覆盖较新的编辑。保存失败时保留当前草稿，明确显示未保存及重试入口。

“恢复选片”与“断点继续分析”分别定义。首轮优先保证选片工作不丢失，分析断点续算后置；如果只能重新分析，也保留原人工决定。关闭页面后纯浏览器任务是否继续运行，不能从保存状态推导。找不到原录像时保留选片记录，引导重新关联，不把其他同名文件直接当成原录像。

### 不混用完成状态

| 界面状态 | 代表的结果 |
| --- | --- |
| 选片已保存 | 对应人工修改和复核状态已经持久保存 |
| 分析完成 | 该录像检测已完成，不表示视频全部缓存或人工复核完成 |
| 音频缓存可复用 | 音频缓存完整且通过校验 |
| 成片已生成或可下载 | 视频生成成功，不表示用户已经保存文件 |
| 成片已保存 | 已有依据确认产物保存在用户可访问的位置；仅发起下载时不使用这一文案 |

## 行为验收场景

| 场景 | 必须满足的结果 |
| --- | --- |
| 导入多份录像 | 无音轨确认关卡；准备失败的单份不清除其他结果 |
| 分析 A 时进入复核，后台继续处理 B | 复核仍停留在用户选中的录像、位置和范围 |
| 快速从 05:00 拖到 35:00 | 最后目标决定画面；旧请求不抢回播放器，分析不随播放头跳转 |
| 拖动局部边界并追加新候选 | 原片播放位置、输入焦点、缩放和人工范围保持正确，未触发整片预处理 |
| 裁边和排除后调整参数 | 人工选片保留，完全重复排除不出现，重叠新候选不默认选中 |
| 分析未结束时提交一批导出 | 只包含该次提交的确定范围，正在补全候选不混入 |
| 提交后继续改范围或调参 | 已排队及已执行批次保持原内容，后续修改属于下一次提交 |
| 自动保存成功后刷新 | 人工操作、排除记录、补充建议状态和复核位置恢复 |
| 保存失败或原片暂不可用 | 不显示虚假成功，不删除人工记录，不误关联其他素材 |
| 刷新时分析或导出未完成 | 显示实际运行或中断状态，不把恢复记录当作断点续算成功 |

## 实现边界与优先顺序

产品规则已收敛，剩余问题以技术验证解决：多音轨自动处理、整文件按需播放的格式兼容性、关键帧定位、单次分析读取与缓存分发、持久化可靠性及资源调度。若真实验证要求改变产品规则，再明确说明具体取舍，不把内部技术参数重新变成用户的必填步骤。

优先验证真实长录像的整文件按需播放与跳转，避免在仍需整片转码的播放路径上重做界面。随后落实自动建议、人工决定和导出批次的独立状态及保存恢复，再将分析队列、复核界面和导出状态接入完整链路。交互示意用于确认操作关系，不替代这些真实能力验收。

后续如生成视频缓存等大文件，遵守用户规定的外接卷路径与容量检查要求；本方案不授权复制整份原视频到本机或浏览器管理的存储中。
