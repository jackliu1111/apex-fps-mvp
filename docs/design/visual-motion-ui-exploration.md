## 2. 三套 skill 的角色与边界

## 3. ALGS 参考站观察

观察范围：2026-10-28，桌面浏览器首屏、现场活动、新闻、选手与积分区域。未完成移动端或全站交互审查。浏览器提示首屏媒体无法播放，不能声称已验证首屏视频、视差、粒子或完整入场动画。以下是视觉分析，不是官方设计分类或实现栈结论。

### 可观察的视觉特征

- 红黑高对比、超大窄体字、巨大品牌形态与角色插画形成首屏视觉中心。
- 背景有颗粒/磨损质感、线描、网格、十字与定位角标。这里的“层”指视觉层次，不断言它们在源码中是独立 DOM 图层。
- 现场照片、人物肖像和关键数字承担不同模块的主要视觉内容。
- 新闻与数据区大量保留安静黑底，让图片和信息突出；并非所有区域都铺满装饰。
- 顶部赛程条、左侧导航在本次滚动观察中持续可见，中央内容与右侧人物/积分形成门户布局。
- 角标、直角边缘、紧凑字体和强调色在不同模块重复，建立一致的赛事界面语言。

分析命名：赛事转播包装 + HUD 式图形语言 + 内容门户布局。HUD 在这里指定位、状态、读数等视觉联想，不表示产品需要复制游戏 HUD。

### 可以迁移与需要重新判断的部分

| 可借鉴的方法 | 迁移到选片工具时需要重新判断 |
| --- | --- |
| 每区有一个明确视觉主体 | 复核区应以录像还是数据为中心，待本轮确认 |
| 图形、字体、控件使用共同规则 | 角标和网格应有受控位置，避免遮挡录像 |
| 展示区丰富、信息区安静 | 品牌入口与高频工作区可以采用不同视觉强度 |
| 大图和真实人物提供情绪 | 本产品优先考虑真实用户录像，官方角色/标志不默认视为可用素材 |
| 强烈标题与强调色 | 中文标题和长时间复核的可读性须单独评估 |

## 4. 游戏画面主导：建议及修正

定义提议：真实录像同时成为第一视觉中心与复核操作中心；候选导航、范围编辑和状态反馈围绕录像组织。大视频背景、自动播放和大播放器都不能单独证明这一目标已实现。

### 可继续讨论的建议

- 播放器优先保持原片比例、完整呈现游戏 HUD，不为填满容器裁掉边缘。
- 游戏画面提供大部分色彩与细节，外围界面用中性色、有限强调色和低强度标记。
- 播放控制与范围编辑靠近画面，文件信息、运行日志和设置减少对主区域的占用。
- 导入后尽早可看原片，稳定候选出现后可开始复核；分析进度不应长期替代可观看内容。
- 展示区域与实际复核区区别处理：前者可试更强主视觉，后者优先完整画面、清晰定位和稳定操作。
- 手机竖屏、超宽录像、密集候选、空状态、原片待关联、后台追加候选等状态需要分别验证。

### 前文建议的状态纠正

- “主列 75%–80%、右栏 260–320px”仅是初始试排建议，没有经过当前双轴界面的验证，不是尺寸规范。
- “右侧候选列表”是候选布局，不能覆盖已经接入的双轴结构；列表是否常驻、折叠或省略仍待决定。
- “保留或跳过后接着复核下一段”容易被理解为自动跳转，与现有确认规则冲突。现有规则为保留/排除不改变播放位置，主动选择下一候选；本轮不改变该规则。
- “拖动边界立即显示对应帧”是体验设想。当前正式接入记录采用拖动时更新范围叠层、松手后定位边界的取舍；不把逐次拖动解码当成已实现或无成本能力。
- “候选/高光”不得混用；品牌文案不能把枪声检测结果表达为已确认精彩或击杀。

## 5. 主题与动效的候选方向

以下全部为建议，未获本轮选择：

| 维度 | 候选方向 | 需要验证的问题 |
| --- | --- | --- |
| 主题 | ALGS 启发的赛事工具语言：黑灰表面、局部红色、适量角标 | 是否适合当前灰褐/珊瑚强调色与复核区的既有分工；不能预先覆盖当前主题 |
| 字体 | 有力度的展示字形 + 易读中文操作文字 + 对齐的时间数字 | 中文字形、窄屏、长文件名和时间刻度的可读性 |
| 背景 | 局部图像/纹理承载品牌，工作区维持安静表面 | 背景是否比录像抢眼，低对比细节是否实际有用 |
| 运动 | 品牌展示短促有力，控件及时反馈，复核时稳定 | 连续播放、拖动、背景分析同时发生时是否干扰或争抢资源 |
| 环境动画 | 仅在适合的展示或空状态试验 | 是否值得持续运动；不默认使用粒子、光晕、扫描线 |

若采用 motion-design 的 Energetic 性格，宜将其理解为品牌节奏参考，而非让所有操作控件回弹。运动距离、时长和曲线待实际任务与状态确定，不在本记录中冻结。

### 第一轮（尚无回答）

1. **范围：是否先聚焦当前正式片段复核页，保留双轴操作规则，分析/导出及宣传展示后续再扩展？** 推荐先聚焦复核，便于判断游戏画面主导是否成立。其他可选范围：三个工作区一起、仅分析/导出、独立展示页。
2. **风格强度：是否采用“ALGS 启发的工具界面”，借鉴有力字形、有限强调色和角标，保持录像周边克制？** 推荐此方向。其他可选强度：接近官网的强海报/材质表达；仅轻量电竞识别。
3. **优先收益：当视觉冲击与复核效率冲突时，是否以更快看清内容、定位和调整范围为第一标准？** 推荐效率优先，风格辨识作为第二标准。也可选择先验证强视觉方向，再收敛工作效率。

### 依赖回答的后续问题（暂不要求回答）

- 具体页面确定后：哪些信息常驻、哪些收起；双轴与播放器空间如何分配；主要屏幕尺寸与高密度场景。
- 风格强度确定后：颜色角色、中文标题处理、角标用途、纹理位置、动效性格；是否需要 Hallmark 安装或只借用描述结构。
- 优先收益确定后：空状态与已导入状态是否用不同主视觉；是否允许环境运动；减少动态效果和实际资源开销的验收方式。
- 实施边界：在现有页面演进还是先做可比较设计稿；必须保留哪些已验证行为。

## 7. 后续验证候选

尚未执行，不宣称效果已达成：

- 同一份真实游戏录像、同一范围、同一视口比较改动前后，避免用更精彩素材冒充设计提升。
- 检查第一视觉中心是否为当前录像，以及播放、裁边、保留/排除的可发现性。
- 检查候选追加、排除、恢复、撤销和页面切换不扰动当前工作，保留现有领域规则。
- 播放、拖动与后台分析并存时观察响应和资源竞争；不因动效增加显著等待。
- 检查键盘、可见焦点、减少动态效果、窄屏与长内容；颜色不作为状态的唯一信号。
- 指标和通过阈值在优先目标确定后再定义；当前没有用户实验、帧率或效率提升结论。
