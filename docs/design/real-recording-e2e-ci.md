# 真实录像上的网页操作验收与 Windows CI

讨论草案，2026-11-28。已确认本轮目标：验证用户实际点击后，页面反馈、后续操作和保存结果符合操作意图。沿用现有声音模型；模型提供候选是流程前提，枪声准确率、交战标注与模型调参均不列入本轮验收。此前 14 张工单的实测结论见[既有回归矩阵](end-to-end-regression.md)。

## 本轮优先级（已确认）

优先检查用户明确发出操作后，页面作用到了错误录像、错误片段或错误时间，后台事件覆盖了用户决定，或者界面报告的工作与实际结果不一致。先用实际点击重现，明确受影响的用户操作，再按票修复和复跑。已修复的问题保留作回归对照。首次打开时从原片开头开始可以接受；首次定位、减少点击次数等便利性设计后置，不作为本轮立项或验收前提。

## 一分钟回归素材约定（用户已确认）

每份样片使用约一分钟的真实 Apex 对局音频。视频轨可采用低分辨率的简化画面，在画面中显示录像标识和随时间变化的帧号或时间码，并与音频共用时间轴。这样可降低 4K 原画的存储和 CI 传输开销，也能从实际显示帧和导出成片中核对录像归属与裁切位置。公开 CI 使用的真实音频也须已获公开分发授权。

## 如何判断一次点击正确

每条用例先写清用户要做什么、屏幕当前显示什么，再写点击位置、期望反馈和下一步能做什么。以“B 的第二段播放到一半，点一次上一段”为例：列表仍选中 B、第一段高亮、画面到达 B 第一段起点；再点播放，应从该处继续。只检查点击事件触发或内部片段 ID 会漏掉播放器仍停在旧位置的错误。

已有文档写明的行为作为回归基线。对于用户意图尚未确认的行为，先在可操作页面演示具体顺序，请用户选择期待的结果，再将它固定成断言。另将持续加载、点不到、误点相邻控件、后台结果晚到和连续点击作为实际操作条件。

## 联动验收表

每行是一组可观察的预期，执行状态另记在测试报告中。对异步切换，从后台事件放行前开始记录加载请求和显示帧；同时检查下一次用户操作，才能发现“列表选对了，按钮却操作另一份录像”的问题。

| 操作或事件 | 应该变化 | 必须保留 | 用哪一步证明 |
|---|---|---|---|
| 从文件框一次选入 A、B、C | 立即出现三行，各自从读取、排队推进到分析完成 | 手动导入路径独立于监听目录的自动离线开关；文件名和结果逐一对应 | 在 B 可复核时点开 B，核对 B 的画面；A 完成后点播放，仍播放 B |
| 暂停在 B 第二段，两个目录开关均开启；目录发现有实时覆盖的 C 和无覆盖的 D | C 复用实时结果，整片离线启动 0 次；D 离线入队 1 次。重复扫描后各一行 | B 的选中项、暂停帧、人工范围；过程中没有切源或重载 | 后台完成后点“上一段”，应到 B 第一段；裁边并导出，再打开成片核对来源和范围 |
| 自动离线关闭，目录发现无覆盖的 D | D 出现一行“未分析”，重复扫描仍未启动离线分析 | 其他录像的任务和人工决定 | 点击 D 的“开始分析”，仅 D 新增一次分析任务，随后 D 行就绪 |
| 点 A 后立即点 B；B 首帧可见后，A 的旧加载结果才返回 | B 的加载完成；A 的旧结果被丢弃 | 从 B 首帧开始始终显示 B，按钮属于 B | 选择 B 第二段并播放，核对 B 的对应画面 |
| 暂停 B 后切走标签页，A 后台就绪，再切回（B4，新预期） | A 行更新为就绪；切回后目录可继续扫描 | B 的原片段、暂停帧、人工决定 | 点“上一段”到 B 第一段；用户主动点 A 才打开 A。原生 Chrome 已验证，见下方实测记录 |
| 实时采集运行时，在页面内有声播放 B | B 正常播放；实时分析因防回环而暂停，界面反映原因 | 监听目录仍关联，当前复核对象仍是 B | 点暂停后核对 B 停在对应帧，同时核对实时状态与实际采集状态一致 |

接入规则按[目录监听约定](../adr/0012-watch-folder-subordinate-analysis.md)在逻辑层逐条验证；浏览器优先串起第二行的完整操作。暂停 B 与播放 B 需要分别验证：前者检查同一帧，后者检查 B 的帧连续向前。新增组合时，注明它能揭露哪一种已有用例观察不到的错误。

## 后续便利性验收：从列表重新打开已复核录像（偏好已确认）

同一会话中，将 A 暂停在第三段中间，点击列表中的 B 并复核，再点击列表中的 A。此时列表选中 A，第三段高亮，实际显示帧回到上次在 A 暂停的位置，误差最多一个素材帧周期。从这里点击播放，画面应从该位置向前推进。用段中位置做对照，可发现只恢复了选中片段却跳回段首的问题。
