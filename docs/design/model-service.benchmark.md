# 本地 Apex 模型服务实测（2026-09-30）

> 历史原型记录：相关执行脚本及旧 TypeScript 导出器已从当前主线移除。复现本文命令请先按 [封存说明](../archive-version0.md) 恢复提交 `d9f2bbd`；当前入口见 [项目说明](../../README.md)。

真实本地 Web 提交、全片推理、候选合并和视频输出已跑通。识别质量按用户要求不评估。建议继续本地 Web + 随包推理进程路线；当前性能压力主要在 4K 精确重编码，而非浏览器界面。

## 范围与环境

- 同一份 3840×2160 / 60 FPS H.264 + AAC 录屏，16.82 GB，1293.93 秒音频；完整 258 个推理窗口。
- macOS 27.0.1 / arm64，BEATs Strong，CPU 4 threads / batch 1，10 秒窗 / 5 秒步长。使用现有 Python 3.12、PyTorch 2.8.0 环境，系统 FFmpeg 和 Bun。
- 浏览器向临时服务提交任务；服务内缓存同一个模型对象，单任务顺序执行。两次分析均重新抽音频、完整推理，没有复用旧帧分数。
- 采用现有 BEATs 推理脚本和 `typescript/src/media.ts` 的 `renderClip`，未修改模型或现有导出器。

## 本次实测

| 阶段 | 首次任务 | 模型常驻后的第二次 |
|---|---:|---:|
| 抽取音频 | 5.85 秒 | 5.29 秒 |
| 模型加载（计入下列任务总计） | 1.72 秒 | 0 秒，复用模型对象 |
| 模型推理循环 | 51.73 秒 | 48.11 秒 |
| 推理任务总计（含加载、后处理、分数与证据写入） | 56.15 秒 | 50.11 秒 |
| 候选合并 | 3.59 ms | 3.93 ms |
| 从录像到候选，不含预览/导出 | **62.59 秒** | **55.50 秒** |

这是同一机器、同一录像的两次测量，不能把全部差值归因于模型缓存：磁盘缓存、CPU 状态等也可能变化。加载本身明确省掉约 1.72 秒。没有云端或其他电脑实测；当前无需为浏览器内推理做模型转换。

| 输出方式 | 测试范围 | 生成耗时 | 输出时长 |
|---|---|---:|---:|
| 原尺寸快速复制 / 三段拼接 | 前三段候选，保留 4K / 60 FPS | **1.59 秒** | 52.612 秒 |
| 现有 720p 预览 / 三段拼接 | 前三段候选，libx264 ultrafast | 16.53 秒 | 49.788 秒 |
| 现有 4K 精确导出 | 第一段，libx264 fast / CRF 18 | **44.33 秒** | 14.483 秒 |
| macOS 硬件 4K 导出 | 同一帧范围，h264_videotoolbox / 80 Mbps | **15.28 秒** | 14.483 秒 |

硬件编码该样本约快 2.90 倍；编码配置不同，未比较画质，不能声称同等质量下该倍率仍成立。硬件编码只是额外独立实验，尚未替换正式导出器。

快速复制请求总时长 49.76 秒，实际 52.612 秒，符合关键帧限制下边界可能扩展的预期；它不提供精确切点保证。720p 三段拼接容器时长约多 28 ms，未验收拼接点逐帧/感知音画同步。

完整测试任务记录的 140.50 秒包含依次尝试三种导出方式以及 15.18 秒的全量解码验收；**不是单一正常导出模式的等待时间**。模型任务总计、加载和推理循环是包含关系，不能重复相加。首次分析后直接快速导出该三段，已测阶段合计约 64.18 秒；不能外推为全部 19 段的导出耗时。

## 已验证

- 两次推理都覆盖 20,702,891 个音频采样，输出 `[32349,447]` 帧分数，没有缺口。
- 两次帧级概率最大绝对差为 0，类别与时间网格一致；这只证明重复执行一致，不证明识别准确率。
- 阈值 0.2 得到 113 条枪声类别候选；按 gap 4 秒 / 前 5 秒 / 后 8 秒生成 19 段候选。
- 四份实际 MP4 输出均经 ffprobe 检查，并由 FFmpeg `-xerror` 全量解码音视频通过。浏览器成功加载 1280×720 / 49.788 秒的真实预览，媒体无错误。
- 音频时间按选定音轨起点 -0.021 秒映射回视频时间；未验收感知音画延迟、关键帧实际内容边界或识别质量。
- 源录像大小和修改时间在任务前后保持一致；未修改原录像、已有权重或历史推理输出。
