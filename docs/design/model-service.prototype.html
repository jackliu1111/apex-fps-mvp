哪些变化需要重跑？

更换模型、音轨或源录像 → 重新推理。调阈值、合并间隔、前后留白 → 复用分数，重算候选。候选变化后清空勾选，避免导出过期选择。

云端只传音频能减少上传量，但本地抽音频和精确视频导出仍需要媒体执行能力；它仍有客户端实现成本。

4 · 枪声候选合并（真实历史候选，未核验精度）

固定使用 21 分 34 秒示例的 Gunshot / Machine gun 事件。上方调整的录像时长仅用于耗时估算，不改变这份候选数据。阈值仅提供历史已解码的 0.1 / 0.2 / 0.5；正式服务应保留帧分数供任意阈值重算。

顺序：跨类别重叠事件取并集 → 按间隔聚类 → 加前后留白 → 裁到源视频范围 → 合并留白造成的重叠。末步避免同一画面重复导出。

这里只导出演示状态。实际 FFmpeg 快速复制的切点受关键帧限制；精确切点需重编码并单独验证音画同步。合并改善观看连贯性，不会提升识别准确率。

待验证的决策与依据

已确认场景：本地录屏离线处理。建议：本地 Web UI + 常驻模型进程，先做一条真实录屏到候选导出的链路。待确认：主要用户系统、可接受等待时间、枪声是否足够代表目标高光。

验收要分别计时：冷启动 / 暖启动、音频抽取、模型推理、后处理、预览和成片导出；至少覆盖 1080p / 4K 的代表性录像。服务进程加载一次模型，任务提交后返回 ID，界面显示阶段与进度。

浏览器内直接推理是额外路线：需转换模型并核验算子、音频前处理、输出一致性和设备速度。已有 .pt 权重不能直接视为浏览器可运行模型。参见 ONNX Runtime Web 官方文档。桌面封装可打包外部执行进程，参见 Tauri 官方 Sidecar 文档。
