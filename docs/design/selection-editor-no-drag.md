# 播放轴与预测区间轴设计（修订）

2026-10-28：用户否定此前无拖动编辑方案。本文件名沿用旧链接，内容以本次修订为准。

## 当前交互

一个播放器，两条轴。默认播放器轴只有可拖动播放头。下方预测轴展示全片六个示例范围；点击预测区间后，上方播放轴显示该段可拖动的左右手柄，视野放大至该段前后各三秒，并标明局部时间刻度。

拖播放头只改变观看位置。拖边界只改变对应端点，另一端不变；视频暂停并预览该边界。手柄不可互相跨越，最短范围 0.1 秒。左右方向键微调 0.1 秒，Shift 为 1 秒。退出按钮或 Escape 隐藏区间手柄并恢复全片播放轴，页面内的修改保留。预测轴同步显示修改后的范围。

本次去掉列表、多选、合并、导出清单和起止输入表单。重点验证点选预测区间后在播放器轴裁剪的基本链路。

## 设计与验证

继续使用 design-taste-frontend 应用界面流程，沿用 True-black flat，seed 2045326786，无重抽。中文系统字体，中性黑色分层，黄绿色表示当前选中范围。界面问题是“预测到了哪段内容，如何看着画面调整切点”。

数据包括完整原片时长、播放位置、预测范围、当前编辑对象和局部视野。播放位置与范围独立维护。六段示例为 4–8、18.2–20.1、20.5–22.4、23–24.6、36–42、51–56.5 秒，不代表真实模型结果。视频和封面使用项目已有一分钟真实 Apex 样本，无外部图片。

最终 1440、768、390 截图全部查看：inspector 0 FAIL / 1 WARN，手机小字号占比警告主要来自两条轴的时间刻度与片段编号；保留紧凑刻度，主要操作文字保持可读。lint 0 FAIL / 1 WARN，警告为合法时间戳补零。浏览器真实鼠标拖动检查通过：默认无范围、点击出现手柄、左边界拖动且右边界不变、播放头不改变边界、Escape 退出，以及三宽度无页面横向溢出。

视觉评审：主体明确为播放器；两个区块同左右边缘；强调色只用于范围；时间读数与范围共享状态；未选中状态清楚；时间刻度无碰撞；手机按播放器、预测轴顺序堆叠。自评清晰度 8/10。剩余问题是手机上密集预测条仍偏窄，后续应增加预测轴缩放；本稿没有宣称已解决长录像数百候选的点选问题。

独立设计稿位于 `model_web_ui/browser.prototype/selection-design/`，预览地址 `http://127.0.0.1:8794/selection-design/`。正式分析、自动保存、导出未接入，修改只在当前页面有效。截图与检查脚本位于 `.taste-skill/selection-editor/revised*`。样本通过已有静态服务读取为临时 Blob，限制 64 MiB，仅用于本设计稿，不改变正式增量播放器。


## 产品研究后的细化（2026-10-28）

官方来源和产品行为边界见 [时间线产品研究](timeline-product-research.md)。以下覆盖上文旧版功能范围与检查数字。

### 已落地到设计稿

- Del / Backspace 排除明确选中的区间，原片、其他范围、播放位置和当前视野保持不变；排除后清空选中，连续按 Del 不误删下一段。
- 可见按钮、Cmd/Ctrl+Z 撤销、Cmd/Ctrl+Shift+Z 重做；一次边界拖动对应一次撤销。拖动中 Escape 取消本次修改。输入控件有自己的按键行为，时间线之外不接管删除。
- “显示已排除”开关显示带划线的轮廓，点击恢复。原始预测数组保留；人工边界变化后，片段 tooltip 明确标注“已调整”及原预测时间。
- 下方同轴显示画面抽样、音频峰值和预测范围，具备缩放、适配全片、前后平移。缩放不改变选片或播放位置。
- 真实样本产生 12 张 240px 宽缩略图，每 5 秒抽样；600 个 0.1 秒音频峰值桶，线性满幅比例。数据和图片合计 94,473 字节，无大文件生成，无外接挂载依赖。
- 悬停画面/波形显示附近采样图及其时间，不修改播放头或选中；点击才定位。图像不是精确指向时刻的逐帧截图。

### 仍在规格阶段

信息层显示开关、精确 hover 解码与过期请求丢弃、局部缩放后更密截图、长录像分级波形及缓存预算、持久化的排除与撤销、模型重算后的决定协调。正式工作区分析和导出未修改。

### 验证与评审

浏览器通过：删除不改变邻段和播放头、撤销/重做、恢复排除、一次拖动一次撤销、悬停不改变播放头、缩放不改变播放头、输入控件删除保护、无选中删除无操作、三宽度无横向溢出、零脚本异常。证据脚本 `.taste-skill/selection-editor/product-check.cjs`。

最终 inspector 1440/768/390：0 FAIL / 0 WARN；已查看三宽度全部截图。保持 True-black flat 方向及原 seed，无重抽。七项复核：播放器仍是主体；上下两区边缘对齐；波形为中性色、选择用强调色；范围和计数同源；排除状态可找回；图片抽样时间有标注；手机需要滚动但缩放仍可操作。清晰度自评 8/10，信息密度 7/10；剩余主要问题是手机纵向长度、信息层开关和精确取帧尚未实现。该自评不代表真实用户测试。

## 原片信息归属修正（用户最终澄清）

画面抽样与音频波形属于上方播放器的原片轨道，不能放在预测区间轨道。当前实现已将两者放入 `play-axis`，与播放头、裁剪边界共用同一坐标和刻度；下方仅保留预测区间、排除/撤销及预测视野控制。

选中范围是叠加在原片上的透明边框。拖动边界只改范围，原片截图和波形不被裁掉、拉伸、重排或重新归一化；播放器视野改变时才按同一原片坐标重绘对应部分。预测轴的缩放独立，不改变上方素材视野。旧章节中“下方展示画面和波形”的描述已被本节覆盖。

新增浏览器断言逐字比较拖动前后的缩略图 DOM 与波形 canvas 数据，验证完全一致。Del、撤销/重做、恢复排除、拖动、hover 及三宽度溢出回归均通过。最终三宽度 inspector 0 FAIL / 0 WARN。


## 正式工作区接入（2026-10-28）

本次已将上下双时间轴接入正式 `app.js`，用真实分析候选与 `review-workspace.mjs` 驱动裁边、排除、恢复、持久化撤销/重做和固定批次导出。早先“正式工作区未接入”的描述仅指当时的原型阶段。原型目录继续保留作为设计参考。

正式实现的性能取舍：拖动预览仅更新范围叠层，松手提交一次修改并定位边界，避免每次 pointermove 发起解码；可见视野读取 10 张小图，60 秒内按需流式生成音频峰值，超过该范围提示放大。暂不承诺长录像的分级波形、逐帧悬停或无性能代价。预测轴缩放独立，原片信息不随裁边重排。精确输入和批量列表保留在折叠区域。

验证与当前限制详见 `model_web_ui/browser.prototype/README.md` 的“正式双时间轴接入”。本次截图和 inspector 报告在 `.taste-skill/selection-integration/`，为本地验证产物，未加入 Git。视觉复核：播放器主体明确；两轴左右边缘对齐；强调色只表达选中范围；时间与数量从状态计算；排除可找回；缺失声音有明确状态；三个宽度无横向溢出。手机纵向长度仍是后续优化点。


### 关键帧参考图与时间显示（2026-10-28 用户补充）

用户明确缩略图只用于辅助查看内容，允许使用关键帧且不需要显示采样时间。正式实现改为取各采样目标之前的已验证关键帧，当前视野内落到同一关键帧的位置复用图片，避免重复解码。悬停仅标注“原片参考画面”，不展示图片采样时间；播放时间、轴刻度与选片起止时间保留。主播放器与裁边定位不变。此规则覆盖上文对缩略图采样时间标注的要求。
