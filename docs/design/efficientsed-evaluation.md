# EfficientSED 录像识别验证设计

状态：2026-11-17 用户确认默认方案并指定录像，已实施独立实验页。浏览器推理与文件内容验收完成；系统原生目录选择窗口尚未验收。操作与证据见 [MODEL-LAB.md](../../model_web_ui/browser.prototype/MODEL-LAB.md)。

## 已确认范围

- 保持纯前端：用户运行时的媒体处理与模型推理在浏览器中进行。Python 仅用于开发阶段的导出与数值对照，不增加推理 API 服务。
- 首轮验证已录制视频的识别质量，包括同一音频模型对照及多类别时间分布；实时输入、流式缓存与实时延迟另行验证。
- 模型底层不限定目标声音类型，输出该 checkpoint 支持的全部类别分数；撤回首轮仅检查五类的建议。
- 前端先按 sigmoid 分数阈值筛选类别，再用 softmax 分配颜色的相对显示面积；该权重仅用于视觉布局，原始 sigmoid 分数仍用于阈值、统计与数值查看。全部低于阈值时显示灰色。
- 全片探索后用户确认：当前可视化仅保留枪声、语音、音乐、脚步、冲击／碎裂五组。先逐帧取组内最大值，概览做时间桶平均，再过滤与视觉 softmax；固定五色图例。其余标签仍保留在原始分数和全类别统计，不参与色带。
- 实验阶段统计真实 Apex 录像中模型高频预测的类别，为后续标签映射和后处理准备依据。预测高频不等于已确认声音高频，映射规则尚未确定。
- 首个实验权重确定为 `fmn10+tf-256_advanced-kd-weak-strong.pt`，保留 EfficientAT 和 BEATs 作对照。
- 全类别逐帧分数通过浏览器写入用户选择的外置硬盘目录，仅服务前期测试。结果分块保存，调整展示和统计参数不要求重新推理；不设计浏览器持久缓存、自动淘汰、存储管理页面或后台续传。
- 外置盘不可写或写入失败时直接报错，不静默改用内置盘。各次实验写入独立目录，不覆盖既有实验。
- 本文中的“浏览器模型推理层”是实现职责描述，不新增为产品领域术语。领域术语仍以 `CONTEXT.md` 为准。

## 当前事实

- `app.js:177` 导入模型固定为 EfficientAT，当前界面没有模型选择入口；底层保留 BEATs 支持。
- `inference-worker.js` 使用 WASM 单线程，当前将非 EfficientAT 的请求路由到 BEATs。
- `browser-analysis.mjs` 只注册两种模型；帧级聚合路径固定 10 秒窗口、5 秒步进、40 ms 时间步。
- Worker 返回完整类别分数，但分析层只保留枪声、机枪声两列。现有候选经过平滑、阈值、留白与合并，不能代替原始预测评估。
- 当前时间轴波形不等于逐类别预测曲线。

## 实施约定与验证说明

- 轻量 `fmn04+tf-104_strong.pt` 可作为首轮质量验证后的性能取舍，不是本轮首个权重。
- 保留 EfficientAT 和 BEATs 作对照；增加独立导出器、模型资产清单和显式 Worker 路由。导出前处理须遵循 EfficientSED，不能直接复用 BEATs 的特征提取。
- 目标适配输出为 `[1,250,447]` 概率，类别顺序以实际 checkpoint 为准；16 kHz、10 秒输入。需要真实导出和数值对照才能确认该契约。
- 全类别统计与界面筛选分别处理：不能仅对前端展示的 Top-K 类别计算统计。建议保留模型原始类别身份，标签映射作为后续可修改的派生视图。
- 建议分别统计阈值以上的时间覆盖、分数分布、事件段数量和类别共现；覆盖按重叠聚合后的原录像时间计算，避免重复计算分析窗口。阈值和事件段连接规则需随统计结果记录。
- 分块保存的容量规划：447 类、25 步/秒的 Float32 一小时约 153.5 MiB，仅为单份概率矩阵，不含其他副本、解码和模型内存。
- 上游推理脚本对帧级输出执行 sigmoid。保存及统计使用未作类别间 softmax 的分数。softmax 不能解释为实际声音占比；阈值后只剩一个类别时，显示权重会成为 1，但其原始分数仍可能很低。
- 质量判断依靠人工核对的事件区间；BEATs 仅作对照，不能当真值。分别记录漏检、误报、起止偏差，以及实际浏览器耗时与内存。

- Q7 接受默认建议：允许连接一串声音中极短的预测断点以减少闪烁；孤立短事件不统一延长成大色块。具体参数尚未确定。
- Q8（已由后续无 softmax 方案替代原“仅固定组色 + softmax 面积”基线）：不采用跨类 `softmax` 共享分母来决定颜色面积；改为各分组按各自预测分数在波形高度内独立分层绘制（详见下节），既不额外增加复杂颜色深浅编码公式，也避免弱预测占满整个波形。
- 用户强调 Q9 的枪声可见性优先，枪声颜色应比其他组更醒目。展示优先级不修改原始预测分数；其他声音不应完全遮蔽已满足显示条件的枪声。

### 修订后的展示方案（面向主分支架构）

本节在初版访谈基础上，吸收了“无 softmax 分层叠画”与“多尺度分辨率金字塔”讨论结论，作为下一阶段设计与原型依据：

1. **目标载体与会话边界**
   - 该方案直接面向**主分支正式选片工作区**（复用 `audio-peaks.mjs` 与 `selection-timeline.mjs`），在单次顺序解码（`sequentialAudio`）的当前内存会话中同步生成振幅峰值与模型预测分数，**不涉及独立实验页“打开已有实验”的持久化波形重开**。
   - 若后续先在 `model-lab.html` 做早期视觉验证，须注意当前实验目录未持久化振幅峰值，届时需补充轻量峰值文件或定义无峰值回退显示。
   - 保持现有分组开关原则：开关只改变展示，不改变原始分数、全类别数据或识别结论；不提供数百个原始标签的选择面板。

2. **波形几何与三态底色**
   - **波形几何**：延续正式工作区现有方式，采用**底部基线向上 + `sqrt(peak)`** 非线性压缩映射，保留低振幅细节高度以承载内部着色；暂不采用使单侧高度减半的中心对称镜像波形。
   - **三态区分**：明确区分“未分析区域（空白或占位）”、“已分析且无关注分组激活（纯中性色不透明波形本体）”与“有关注分组激活（在波形轮廓内部叠画前景层）”。
   - **音轨可见性**：沿用既有音轨策略；若分析自动回退到非默认可解码音轨，在波形状态区保留音轨编号提示，避免用户误解波形与试听声源。

3. **无 softmax 独立前景分层叠画（参考 Mixxx `Filtered` 思路）**
   - **取消跨类 `softmax` 面积分配**：保留模型原始 `sigmoid` 多标签输出，各分组独立计算前景绘制高度（如按 `score × waveHeight` 或阈值过滤后的独立比例），**各组之间不共享分母**，避免滚轮缩放改变统计窗口、开关部分分组或单个弱预测过阈值时导致其他组高度突变或弱预测占满 100% 波形。
   - **枪声外缘前景优先**：底层为完整中性色不透明振幅波形；**枪声**作为最前景高醒目色从波形顶部外缘（振幅包络顶线）向下绘制；其余启用的关注分组以低饱和度/半透明图层按固定前后顺序叠画在波形内部底侧，确保其他声音不遮蔽枪声。
   - **语义与色彩约束**：
     - 独立叠画高度仅反映各分组的预测置信强度，不表示声音的音量占比、真实标签或人工确认事件（术语遵循 `CONTEXT.md`）。
     - 正式工作区选中片段遮罩与裁边手柄使用天蓝色（`#60a5fa` / `rgba(59, 130, 246, 0.12)`），接入主分支时**语音分组色彩须避让选区天蓝**（现 `lab-display-groups.mjs` 为 `#568bc8`），并拉开枪声醒目色与其他分组（如现 `#e87743` 与 `#c4a044`）在浅色工作区与中性波形底色上的明度/色相区分度。

4. **多尺度流畅缩放与渲染分层（保留轻量 Canvas，借鉴 BBC `Peaks.js` 架构思路）**
   - 保留本仓库轻量自研 `audio-peaks.mjs` + `selection-timeline.mjs` Canvas 架构，不整体引入 `Peaks.js` 或 `Wavesurfer.js` 等重型外部库，仅采用其核心设计模式：
   - **Overview + Zoomview 双视图与共轴对齐**：复用正式页上方全片概览条（`#player-overview-bar`）与下方局部可缩放主时间轴（`#source-axis`）；全链路统一使用原片视频时间坐标 `[0, videoDuration]`，模型预测帧位置统一应用 `audioOffset` 对齐波形，解决局部截断或音视频起始偏移造成的错位。概览条按需同步显示缩略枪声分布。
   - **多级分辨率金字塔缓存**：按多档预设时间粒度增量维护多级分辨率视图（参考 `Peaks.js` `zoomLevels` / 缓存层级思路），滚轮缩放与平移时直接切片对应层级数据，避免每次缩放全量重算长录像；在缩略层级对枪声等关键事件**按输出像素列取峰值（`max`）**保留存在性，消除时间桶均值稀释短点射以及同像素列后帧覆盖前帧的问题；放大到局部细节时切换细粒度乃至 40 ms 逐帧视图。
   - **游标与交互叠加层分离**：播放游标针、选区遮罩与悬停读数浮层独立于底层波形着色 Canvas，播放推进与拖动定位仅更新叠加层，不触发底层波形重绘；鼠标悬停时间轴应提供对应位置的时间与分组分数读数。

### 实现边界与待收口验证重点

现有代码具备波形峰值与原片播放的基础能力，目前未发现阻止该方向实现的结构性问题。以下边界仍待后续视觉原型与实测验证，不代表已经通过验收：

- 实验页目前没有实际波形显示，播放时现有分类色带游标也未联动；后续原型或主分支接入时需先验证音视频偏移 `audioOffset` 下的音画/波形/游标对齐与分层渲染性能。
- 低振幅区枪声可见性仍需实测：远距离枪声或近静音位置出现高分预测时，仅靠波形内部高度（`score × waveHeight`）仍可能只有 1–2 像素甚至不可见；后续需用真实 apex 战斗片段检查是否需要最小外缘像素厚度或顶边指示补偿。
- 多层半透明/独立叠画在 2–4 个非枪声分组同时出现高分时的视觉混叠清晰度、语音替换后的最终配色板、阈值截断线（如低于阈值完全不画 vs 连续 `score` 绘制）以及 Q7 极短断点连接参数，留待实际界面预览确认。
- Q7 的断点连接只作用于派生展示，不覆盖保存的原始分数，也不作为人工确认事件或正式选片依据。
- 用户当前授权止于文档记录，不据此自动进入代码实施。
