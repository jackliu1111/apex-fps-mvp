# EfficientSED 录像识别验证设计

状态：2026-11-17 用户确认默认方案并指定录像，已实施独立实验页。浏览器推理与文件内容验收完成；系统原生目录选择窗口尚未验收。操作与证据见 [MODEL-LAB.md](../../model_web_ui/browser.prototype/MODEL-LAB.md)。

## 已确认范围

- 保持纯前端：用户运行时的媒体处理与模型推理在浏览器中进行。Python 仅用于开发阶段的导出与数值对照，不增加推理 API 服务。
- 首轮验证已录制视频的识别质量，包括同一音频模型对照及多类别时间分布；实时输入、流式缓存与实时延迟另行验证。
- 模型底层不限定目标声音类型，输出该 checkpoint 支持的全部类别分数；撤回首轮仅检查五类的建议。
- 前端先按 sigmoid 分数阈值筛选类别，再用 softmax 分配颜色的相对显示面积；该权重仅用于视觉布局，原始 sigmoid 分数仍用于阈值、统计与数值查看。全部低于阈值时显示灰色。
- 当前可视化仅保留枪声、语音、音乐、冲击／碎裂四组。2026-11-18 用户确认：脚步预测过多，移除脚步展示组以减少视觉干扰；独立实验保留全部原始类别分数和全类别统计。实验页先逐帧取组内最大值，概览做时间桶平均，再过滤与视觉 softmax；正式复核页采用下文的无 softmax 独立分层规则。
- 实验阶段统计真实 Apex 录像中模型高频预测的类别，为后续标签映射和后处理准备依据。预测高频不等于已确认声音高频，映射规则尚未确定。
- 首个实验权重确定为 `fmn10+tf-256_advanced-kd-weak-strong.pt`，保留 EfficientAT 和 BEATs 作对照。
- 全类别逐帧分数通过浏览器写入用户选择的外置硬盘目录，仅服务前期测试。结果分块保存，调整展示和统计参数不要求重新推理；不设计浏览器持久缓存、自动淘汰、存储管理页面或后台续传。
- 外置盘不可写或写入失败时直接报错，不静默改用内置盘。各次实验写入独立目录，不覆盖既有实验。
- 本文中的“浏览器模型推理层”是实现职责描述，不新增为产品领域术语。领域术语仍以 `CONTEXT.md` 为准。

## 当前事实（2026-11-17 初版排查基线，现已接入正式工作区）

- 历史基线中 `app.js:177` 曾固定使用 EfficientAT；现已通过 `model-registry.mjs` 将正式工作区默认模型切换为 `efficientsed`（`DEFAULT_MODEL = 'efficientsed'`），同时保留 `efficientat` 与 `beats` 作对照与扩展路由。
- `inference-worker.js` 使用 WASM 单线程，按模型清单显式路由至 EfficientSED（16 kHz / `efficientsed-frontend.mjs`）、EfficientAT（32 kHz）或 BEATs（16 kHz）。
- 帧级聚合路径固定 10 秒窗口、5 秒步进、40 ms 时间步，通过 `FrameOverlap` 对重叠窗口做跨原始类别平均后再映射为四组展示分数与多级金字塔缓存。
- 正式选片工作区在内存会话中保留枪声候选原始两列（用于 `candidatesFromScores` 候选派生与阈值重算）及四组逐帧分数与金字塔（仅服务展示层与悬停读数，不持久化）。

## 实施约定与验证说明

- 轻量 `fmn04+tf-104_strong.pt` 可作为首轮质量验证后的性能取舍，不是本轮首个权重。
- 保留 EfficientAT 和 BEATs 作对照；增加独立导出器、模型资产清单和显式 Worker 路由。导出前处理须遵循 EfficientSED，不能直接复用 BEATs 的特征提取。
- 目标适配输出为 `[1,250,447]` 概率，类别顺序以实际 checkpoint 为准；16 kHz、10 秒输入。需要真实导出和数值对照才能确认该契约。
- 全类别统计与界面筛选分别处理：不能仅对前端展示的 Top-K 类别计算统计。建议保留模型原始类别身份，标签映射作为后续可修改的派生视图。
- 建议分别统计阈值以上的时间覆盖、分数分布、事件段数量和类别共现；覆盖按重叠聚合后的原录像时间计算，避免重复计算分析窗口。阈值和事件段连接规则需随统计结果记录。
- 分块保存的容量规划：447 类、25 步/秒的 Float32 一小时约 153.5 MiB，仅为单份概率矩阵，不含其他副本、解码和模型内存。
- 上游推理脚本对帧级输出执行 sigmoid。保存及统计使用未作类别间 softmax 的分数。softmax 不能解释为实际声音占比；阈值后只剩一个类别时，显示权重会成为 1，但其原始分数仍可能很低。
- 质量判断依靠人工核对的事件区间；BEATs 仅作对照，不能当真值。分别记录漏检、误报、起止偏差，以及实际浏览器耗时与内存。

## 后续展示设计访谈、方案定稿与浏览器验收（2026-11-17）

状态：已按以下修订方案接入主分支正式选片工作区，并完成真实 Apex 战斗样本（`sample-combat.mp4`）与低振幅/短事件/多组重叠合成样本的 Chrome 无头浏览器截图审查、视觉参数定稿与全链路 OPFS 导出验收。以下参数已固化在 `lab-display-groups.mjs`、`waveform-layers.mjs` 与 `selection-timeline.css` 中。

- 前端需要兼顾通用视频声音识别，主要用途仍是游戏自动判别，枪声更重要。
- 保留枪声、语音、音乐、冲击／碎裂四组预设；相似类别应合并展示，以控制颜色数量。不能要求每份录像先人工挑选预测覆盖较高的类别才能渲染。
- 用户提供的参考形态为不透明的完整波形，在波形内部局部着色；不采用独立类别区域作为默认方案。类别选择与底色规则见下文。

### 已确认规则与最终视觉参数

- **固定四组与开关隔离**：枪声、语音、音乐、冲击／碎裂四组默认启用，允许用户在时间轴上方开关任意展示分组；相似原始标签的合并由系统固定维护（`lab-display-groups.mjs`），不向用户暴露 447 类原始标签面板。切换分组仅重绘波形/概览，不改写原始 `声音预测分数`、`枪声候选片段` 或 `人工复核决定`。
- **波形几何与三态底色**：采用底部基线向上的离散柱状波形：主时间轴柱间距 `4 CSS px`、柱宽 `2 CSS px`，概览柱间距 `2 CSS px`、柱宽 `1 CSS px`；不足 60 柱时回退为逐物理像素绘制。离散柱模式先对峰值应用权重为 `[0.14, 0.22, 0.28, 0.22, 0.14]` 的五点平滑（忽略缺失邻点并归一化，未分析列仍留空），再采用 `peak^0.56 × 0.92` 振幅映射；逐像素回退保留 `sqrt(peak)`。这些变换仅作用于显示。离散柱模式对已分析峰值应用五点对称核（`0.14 / 0.22 / 0.28 / 0.22 / 0.14`），再用 `peak^0.56 × 0.92` 映射振幅；逐像素回退模式沿用 `sqrt(peak)`。未分析列保持空白，平滑只作用于展示投影，不修改原始峰值或模型分数；明确区分“未分析区域（空白）”、“已分析且无关注分组激活（不透明中性灰 `#7b8391` 完整波形本体）”与“有关注分组激活（前景叠层着色）”。回退到非默认可解码音轨时在状态栏提示音轨编号。
- **最终分组色板与叠层透明度**（浅色轨道 `#f5f6f8` + 中性灰波形 `#7b8391`，避让选区天蓝 `#60a5fa` / `#3b82f6`）：
  - `枪声`（`gunshot`，`top` 外缘顶边向下绘制，最前景最后绘制）：`#dc3b26`（朱红，色相 ~7°），波形层 `alpha: 0.96`，全片概览条 `alpha: 0.92`。
  - `语音`（`speech`，`bottom` 内部底侧向上）：`#4e9c46`（鼠尾草叶绿，色相 ~114°，与选区天蓝 215° 保持 >100° 色相差，替换早期冲突色 `#568bc8`），`alpha: 0.64`。
  - `音乐`（`music`，`bottom` 内部底侧向上）：`#8868c8`（柔和紫，色相 ~260°），`alpha: 0.58`。
  - `冲击／碎裂`（`impact`，`bottom` 内部底侧向上）：`#cf922c`（暖琥珀，色相 ~38°），`alpha: 0.62`。
  - **选区配合调整**：全片概览条选中高亮 `#player-overview-markers > span[data-active="true"]` 使用 `rgba(59, 130, 246, 0.24)` 与 `#3b82f6` 边框，主时间轴 `#selection-overlay` 下边框收敛为 `1px solid rgba(59, 130, 246, 0.55)`（上边框保持 `2px` `#60a5fa`），保证红色枪声指示不被遮挡。
- **显示阈值截断方式**：采用硬阈值截断 **`score >= 0.2`（`DEFAULT_DISPLAY_THRESHOLD = 0.2`）**。低于 `0.2` 的帧不绘制彩色叠层，保持中性灰 `#7b8391` 轮廓以防止低分微弱噪声把整条波形染成杂色；鼠标悬停 `#source-hover` 始终通过 `groupScoresAtTime` 展示包括 `< 0.2` 在内的 4 组原始分数。
- **低振幅区枪声最小外缘厚度（实测拍板）**：经低振幅（`peak = 0.0005`、`waveHeight = 1–2 px`）与选区遮罩叠加截图对照，无保底厚度时 `1 px` 枪声会被选区底边完全淹没。现已固化 **`DEFAULT_MIN_GUNSHOT_PX = 4`（`4 CSS px`，按 `dpr` 缩放）**：当 `waveHeight < 4 CSS px` 且枪声 `>= 0.2` 时，自基线向上维持 `4 CSS px` 顶边指示；正常振幅（`waveHeight >= 4 CSS px`）仍按 `round(score * waveHeight)` 自波形顶缘 `waveTop` 向下绘制。
- **Q7 极短断点连接参数（纯展示层）**：固化 **`DEFAULT_GAP_BRIDGE_MS = 80`（即 40 ms 帧率下最多 `2` 帧的同组内部凹陷）**。仅当同组在 `<= 80 ms` 内部低谷两侧均存在 `>= 0.2` 的激活帧时，在展示投影层以两侧边缘帧较低分数（`min(leftScore, rightScore)`）平滑连接，采用 `O(width)` 邻域有界查表，不在缩放/平移时扫描全片。**孤立短事件外边界绝不延长**，且绝不修改 `record.scoreTimeline.groupScores`、`record.scores`、`record.scoreTimeline.groupScorePyramid`、`record.candidates`、`groupScoresAtTime` 原始悬停读数、人工复核决定或导出批次。

### 修订后的展示方案（主分支实施摘要）

1. **目标载体与会话边界**：直接运行于主分支正式选片工作区，单次顺序解码（`sequentialAudio`）同步生成振幅峰值与模型分数，遵循 ADR 0005 / ADR 0006 页面会话边界，刷新即清空。
2. **无 softmax 独立前景分层叠画**：保留模型原始 `sigmoid` 多标签输出，各分组独立按 `score × waveHeight` 计算厚度，彼此不共享分母；枪声置顶，非枪声组按固定顺序叠画于波形底侧。
3. **多级分辨率金字塔与独立叠加层**：`pyramid-cache.mjs` 与 `waveform-layers.mjs` 增量维护振幅与 4 组 `max` 金字塔，缩放/平移切片不重算全片，缩略列保峰不稀释短枪声；游标、选区、悬停浮层与底层波形 Canvas 分离，播放定位不重绘波形。

- **未验证边界（保持透明）**：
