# Apex 枪声模型服务方案：共享 Python 引擎与双服务入口

整理日期：2026-10-02（Asia/Shanghai）。依据 2026-09-30 起的方案讨论与实测交接。

状态：处理规则与首版范围已确认；服务方向确定为共享 Python 推理引擎，由 Electron 桌面服务和轻量 Python Web 服务分别承载。下述模块组织和接口细节为实施建议，尚未接入正式应用。人工标注与训练数据整理放到后期，不作为首版交付条件。

术语见 [CONTEXT.md](../../CONTEXT.md)，范围决策见 [ADR 0001](../adr/0001-audio-model-first.md)，双服务入口决策见 [ADR 0002](../adr/0002-shared-python-engine-dual-hosts.md)。本方案新增模型枪声模式，不替换既有伤害分析或音频能量模式的语义和规则。

## 目的与范围

用户希望方便地处理本地 Apex 录屏：用已有预训练模型定位枪声候选，复核后导出多个独立片段，并为后续模型训练和更换保留接口。先在当前 Mac 上完成离线处理链路，再分别验证 Windows 和 Mac 的桌面发行包；识别质量随后评估。

Electron 入口面向最终用户，提供可安装、双击启动的桌面体验；Python Web 入口面向内部测试，便于快速启动、查看日志和替换模型。两套服务复用同一 Python 推理实现、候选规则和结果契约，不形成两套独立算法。

首版包括本地录像选择、纯音频模型推理、候选生成、参数调整、预览复核、导出范围调整和独立片段导出。模型枪声流程不进行截图、HUD/OCR 或画面检测；用户人工观看录像复核不受此限制。

当前枪声候选不等于本人开枪、命中、击杀或精彩操作。后期计划识别本人开枪或命中，但这些目标需要新的标注、训练和独立验证，不能由通用枪声分数直接推导。

## 已确认的处理规则

| 项目 | 首版规则 |
|---|---|
| 运行场景 | 本地录屏、离线分析；先在当前 Mac 验证，桌面分发面向 Windows/Mac 分别构建 |
| 服务入口 | Electron 桌面服务用于分发；轻量 Python Web 服务用于内部测试 |
| 检测输入 | 音频，暂不结合画面自动检测 |
| 初始模型 | 使用 apex-voice-detect 中已有的枪声检测基线 |
| 合并间隔 | 上一事件结束到下一事件开始的间隔不超过 5 秒 |
| 前后留白 | 分组后前 5 秒、后 5 秒，裁剪至录像有效范围 |
| 持续交火 | 不设强制拆分时长，不在持续交火中硬切 |
| 留白重叠 | 允许不同片段重叠，不因为留白重叠再次合并 |
| 复核 | 默认预选，支持预览、取消选择与调整起止范围 |
| 输出形式 | 每个选中的片段分别导出，不默认拼成单个集锦 |
| 导出方式 | 默认关键帧快速复制，允许范围偏移，预留精确重编码 |
| 标注编辑 | 后期实现，独立保存，不覆盖原始预测 |

例如两个事件之间相隔 7 秒，应分成两组。双方各留白 5 秒后虽然重叠，仍分别导出。不能沿用原型中“留白后再次合并”的步骤，否则实际分组间隔会超过用户设定的 5 秒。

用户偏好较短的开枪片段，但允许持续交火形成较长候选；5 秒间隔与前后留白并不保证固定或很短的片段长度。

## 架构与职责

一个共享 Python 推理引擎，两套可独立启动的服务入口。建议将模型枪声模式的业务处理提取为共享 Python 任务核心，包含媒体调用、模型适配、候选后处理和结果存储；推理引擎作为其中独立模块。两个服务入口只做传输适配与宿主生命周期管理，避免在 Electron 和 Python HTTP 服务中各维护一份合并规则。

```text
Electron 桌面入口                         Python 内部测试入口
React/TypeScript 界面                     浏览器中的 Web 界面
    ↓ IPC                                    ↓ HTTP
Electron/Node 主进程                      轻量 Python HTTP 服务
    ↓ 标准输入/输出命令                      ↓ Python 调用
Python 常驻任务进程                       后台任务执行器
    └─────────────────┬──────────────────────┘
                      ↓ 复用同一套实现
              共享 Python 任务核心
                ├─ 模型适配与推理引擎
                ├─ 事件判定与候选后处理
                ├─ FFmpeg/ffprobe 媒体操作
                └─ 预测、候选及导出结果存储
```

图中的共享指代码与契约复用，不要求两个入口同时运行或共享同一个内存模型。每个运行实例拥有自己的模型和任务状态；默认使用不同数据目录，如需打开同一目录，必须有互斥锁，避免相互改写任务记录。

| 边界 | 责任 |
|---|---|
| React/TypeScript 界面 | 展示任务、曲线和候选，提交操作；通过传输适配层选择 Electron IPC 或 HTTP |
| Electron 主进程 | 桌面窗口、文件选择、单实例、用户目录、Python 进程启动和退出；转发命令与任务事件 |
| Python HTTP 服务 | 静态页面与测试 API、请求校验、提交后台任务、查询状态与返回媒体内容；运行时不依赖 Electron 或 Bun |
| 共享 Python 任务核心 | 统一任务状态、取消逻辑、源文件校验、媒体流程、候选版本和持久化规则 |
| 模型适配与推理引擎 | 模型只加载一次并复用，处理权重格式、类别顺序、输入前处理与模型输出差异 |
| 候选后处理 | 消费统一预测结果，产生事件和候选；不加载模型，不依赖 IPC/HTTP |
| 媒体工具层 | 保持音轨和时间轴一致，通过 FFmpeg/ffprobe 执行抽音频、预览及导出 |

### Electron 桌面服务

建议技术栈为 Electron + React/TypeScript，Node 主进程通过 `child_process.spawn` 启动打包后的 Python 常驻任务进程。界面经 preload 暴露的有限 IPC 操作调用主进程；主进程与 Python 使用带请求标识的标准输入/输出消息，进度与结果按事件返回，日志写到标准错误或日志文件。

桌面业务调用不依赖本地 HTTP 服务或用户安装的浏览器。预览媒体通过受控的本地资源协议提供，并保留视频定位所需的范围读取能力。主进程负责模型进程就绪、重复启动处理、异常通知和退出清理；这些行为需要实现，不能视为 Electron 自动提供完整的推理进程管理。

既有 React 界面和不依赖运行时的 TypeScript 逻辑可以复用。现有 Bun Web 服务是迁移参考，`Bun.serve/file/spawn/write` 等调用需要适配；不将 Bun 作为新的桌面发行包必需运行时，也不要求 Electron 通过打开旧 `localhost` 页面运行。

### 轻量 Python Web 服务

建议采用 FastAPI + Uvicorn 单服务进程，提供测试 API 和必要的 Web 页面。具体框架尚属实施选择；关键是直接复用 Python 任务核心，不重复实现候选规则，不要求先构建桌面安装包才能测试模型。

内部测试可用受控 Python 环境启动，显式配置模型与 FFmpeg 路径，支持查看日志、切换模型和检查中间结果。“轻量”指服务层和启动流程简化，PyTorch 与模型权重仍是实际运行依赖。

模型加载后复用，耗时任务交给单活动任务执行器，避免阻塞 HTTP 请求和进度查询。默认关闭自动重载和多 worker，避免重复加载模型。复用前端时由 Python 提供已构建的静态文件；前端构建工具仅用于开发和构建，不是内部服务运行依赖。

内部测试默认监听回环地址，并保留访问令牌和请求来源校验。关闭网页后任务仍可继续；停止服务时应取消任务并清理媒体进程。内部测试入口不自动扩展为局域网多人服务，远程访问和并发调度另行设计。

### 共同生命周期约束

首版每个实例只执行一个活动任务，顺序处理选中的录像，模型常驻复用。共享任务核心负责执行状态与取消，入口负责将用户动作和进程退出传递到核心；不能让每个任务重新创建一套模型。

核心可以正常处理的异常由核心写入任务终态；核心进程直接崩溃时，仍存活的入口负责报告故障，不能假定已经退出的核心还能保存错误。核心下次启动时检查持久化记录，将遗留执行中任务标记为失败并注明服务中断，保留已完成产物；后续任务可以重新启动引擎。自动断点续算不属于首版范围。两个入口对同一错误应给出一致的错误类型和任务终态。

## 处理流程与结果契约

1. 校验录像和媒体信息，确定用于检测的游戏音轨。多音轨时不能默认为第一轨一定包含游戏声音；缺少可用音轨时给出明确错误。
2. FFmpeg 抽取音频。当前 BEATs 基线使用 16 kHz 单声道、10 秒窗口、5 秒步长；这些属于模型适配参数，不是导出片段长度。
3. 常驻引擎执行推理并保存帧分数。当前输出步长为 40 ms（25 Hz）；这表示预测网格，不表示事件边界已经达到 40 ms 准确率。
4. 按类别和阈值生成枪声候选事件，再按已确认规则生成候选片段。
5. 用户按需预览，取消误选或修改请求导出范围。
6. 按原录像顺序为选中的候选分别输出视频，记录请求范围、实际覆盖范围及输出路径。

建议结果至少包含以下信息，具体字段名称在接入时与现有类型统一：

| 结果层 | 必须保留的信息 |
|---|---|
| 源媒体 | 源文件身份、大小/修改时间、媒体时长、选定音轨及起始时间信息 |
| 原始预测 | 结果版本、模型/权重标识、类别标识与顺序、帧分数、帧时间网格、有效长度、前处理版本 |
| 枪声候选事件 | 事件类别、原录像起止时间、所用预测版本和后处理配置 |
| 候选片段 | 候选标识、版本、事件来源、分组及留白后的起止范围 |
| 导出选择 | 对应候选版本、选中状态、用户调整后的请求范围 |
| 导出记录 | 快速/精确模式、请求范围、实际范围、输出文件及执行结果 |

统一以原录像视频时间轴表示候选和请求范围，并记录从音频时间到该时间轴的映射。音轨选择与时间映射必须贯穿抽取、预测、预览和导出；不能把实测样本的起点差硬编码到其他录像。

模型适配层建议统一提供“时间 × 类别”的分数及时间和类别元数据。后续 BEATs 更换为 ATST-F 或 Apex 自定义模型时，服务任务、复核和导出可复用，但加载器、类别映射、前处理与阈值仍可能需要调整；不承诺只替换权重文件即可升级。

## 调参、缓存和接口接入

模型推理与候选后处理分开。调整阈值、合并间隔或留白，只重算候选；更改音轨、源文件、模型或输入前处理时，应重新推理。原始分数不能被阈值处理结果或后期人工标注覆盖。

缓存键包含源媒体身份、音轨、模型/权重、前处理与结果版本。沿用当前文件大小和修改时间检查时，应保留其无法识别“大小和修改时间均相同的内容替换”这一限制。

每次候选重算创建新版本，使旧预览与选择失效，并提示需要重新复核。预览不能仅按原分析标识和列表位置缓存，否则修改范围后可能播放旧片段。仅修改请求导出范围时更新相应预览与导出选择，不修改原始预测。

两个入口使用同一组逻辑操作和结果格式，分别映射到 IPC 和 HTTP；优先沿用既有分析、任务查询、取消、预览和导出的用户语义：

- 分析入口新增明确的模型枪声模式，以及模型和音轨配置；不要把现有音频能量结果改称模型置信度。
- 增加基于已有预测结果的候选重算能力，返回新的候选版本；具体 HTTP 路由和 IPC 命令名待接口设计。
- 导出入口扩展为候选版本、候选标识、选中片段的请求范围和导出模式；校验范围合法性、源文件身份及过期选择。
- 任务查询提供阶段进度、错误、阶段耗时和输出记录；模型启动/加载失败必须可见。

两个入口应共享请求/结果 schema、任务状态、事件类别、错误类型、时间单位和结果版本。内部传输可不同，但不能让桌面入口和测试入口解释出不同的合并、留白或导出行为。

推理结果属于共享任务核心的持久化产物，大体积帧分数通过结果引用读取，无需通过普通任务查询、IPC 或标准输出完整传给界面。曲线和复核数据可以按当前查看范围读取；采样用于显示，不能替代原始预测结果。

## 导出与预览边界

快速复制保持兼容源流，通常比重编码更快，但起止点受关键帧与容器限制。记录并展示请求范围与实际覆盖范围的差异，不把用户在界面调整的时间描述为已经精确执行。具体边界选择策略与实际范围测量仍需媒体层验证。

源编码或容器不支持直接复制时，给出明确说明；若需要精确重编码，应由用户明确选择，避免静默改变等待时间或输出特性。首版至少定义快速复制和精确重编码的接口位置，默认启用快速复制；精确模式是否同批交付在实施时按已有导出器适配情况确定。

独立输出按录像区分目录并编号，重复导出不覆盖已有文件。取消或失败时清理当前未完成文件，保留已完成片段及对应记录。预览按需生成，避免分析完成前就为全部候选重编码。

## 构建与分发

| 入口 | 推荐交付方式 | 使用者环境 |
|---|---|---|
| Electron 桌面服务 | electron-builder 生成 Windows 安装程序、Mac `.app`/DMG；Python 任务核心用 PyInstaller `onedir` 随包分发 | 不要求安装 Python、Bun、Node、PyTorch 或 FFmpeg |
| Python 内部测试服务 | Python 包/源码与依赖清单、配置及启动说明，加载同一任务核心 | 内部人员准备受控 Python 环境、权重和 FFmpeg；需要时可额外生成便携包 |

桌面包包含 Python 完整运行目录、模型权重、类别配置以及目标平台的 FFmpeg/ffprobe。Python 运行目录作为可在真实文件系统执行的资源分发，保留其动态库、执行权限及符号链接，不塞入只能由 JavaScript 读取的应用归档中。模型与应用记录各自版本和兼容性，路径基于安装资源目录定位，数据与日志写入用户目录。

先验证 Mac arm64，Windows x64 另行构建和验收；Intel Mac 或 Windows arm64 是否支持取决于后续需求与整套依赖验证。基线采用 CPU 推理，MPS/CUDA 加速单独评估。

Electron 提供成熟的桌面与安装包工具，但不消除 Python 原生依赖、系统最低版本、Mac 签名公证和 Windows 系统信任问题。两平台分别构建完整产物，在没有开发环境的机器上验证启动、推理、预览、导出和退出。当前 ZIP 打包器对 Python 目录的符号链接与执行权限处理不足，应在新发行流程中替换或修复，不能直接把推理目录塞入旧 ZIP 流程。

## 现有证据与实现缺口

2026-09-30 实测来自原型分支 `codex/prototype-apex-model-service`、提交 `d9f2bbd` 中的 `docs/design/model-service.benchmark.md`。该报告不在当前工作树中，可用 `git show d9f2bbd:docs/design/model-service.benchmark.md` 查看；本文不把原型能力写成正式产品能力。

- 实测使用 BEATs Strong 通用声音模型、macOS arm64 CPU 4 threads；不是已完成 Apex 微调的模型，也不是 ATST-F 性能结果。
- 同一份 1293.93 秒、4K/60 FPS 录像，首次分析 62.59 秒、常驻后的第二次 55.50 秒；模型加载自身节省 1.72 秒，不能把全部时间差归因于模型常驻。
- 快速复制只测了前三段候选的拼接样本，耗时 1.59 秒；不能作为全部候选或本方案多个独立输出的已测耗时。
- 四份实测输出通过全量音视频解码，但识别质量、感知音画同步、切点内容和独立安装包尚未验证。
- 原型使用合并间隔 4 秒、前 5 秒/后 8 秒并再次合并重叠，得到 19 段；本方案改为 5/5/5 且不因留白重叠合并，不能沿用原型候选数量作为新规则结果。
- 当前正式 TypeScript 音频模式仍基于 RMS 能量，现有媒体导出主要为重编码；Electron 入口、轻量 Python 测试入口、共享任务核心、常驻模型接入、分数缓存重算和正式快速复制路线均尚未完成。

## 验证与推进顺序

建议以逻辑服务操作为主要测试边界：复用同一组行为场景，通过 HTTP 和 Electron IPC 两种适配器提交任务、查询结果、修改范围、预览和导出。现有本地应用的完整流程检查可作为先例；不为内部函数组织单独增加测试约束。

1. 先固定共享任务核心、模型适配结果、任务操作与候选版本契约，提取可独立调用的 Python 实现。
2. 先接入轻量 Python Web 服务，复用现有界面完成模型分析、调参、复核和独立片段导出的内部测试闭环。
3. 接入 Electron 主进程与 IPC，复用同一套前端和 Python 核心；将与 Bun 绑定的运行时调用替换为对应实现。
4. 让两个入口运行同一来源、模型版本和参数，比较帧分数（使用明确数值容差）、事件/候选区间、导出请求范围和错误语义；任务 ID、文件路径及耗时等运行元数据无需相同。
5. 覆盖 5 秒间隔分组、边界留白、留白重叠不合并、持续交火不拆；验证调参不重跑模型，旧选择与预览不会误用。分别验证取消、引擎异常、源文件变更、无候选、正常退出和主进程异常退出后的子进程清理，以及重启时遗留任务状态的收敛。
6. 通过两个入口跑代表性真实录屏，保留结果、阶段耗时、完整选片导出记录及音视频解码检查；实际切点和感知同步需单独复核。
7. 分别验证 Windows/Mac 桌面安装包，以及脱离 Electron/Bun 的 Python 内部服务。桌面包需覆盖普通用户、中文/空格路径、移动安装位置、断网和重复启动；构建成功或 HTTP 健康响应不等于完整验收。

模型效果评估单列后续工作：包含独立来源录像上的误报、漏报、复核成本和候选是否有用。当前单样本性能数字作为参考，不作为其他设备、模型或录像的性能承诺；可接受等待时间和最低识别质量目标仍待后续评估确定。

## 后期标注与训练扩展

本阶段不实现标注编辑器、训练数据生成或训练任务。当前只保留原始预测、类别与时间元数据、源录像身份及版本信息，为后续扩展提供依据。

已经讨论确定的后期方向为：

- 人工修订独立保存；“枪声”和“本人开枪”分别标注，归属不明保留未知，命中目标另行定义。
- 当前标注按 40 ms 网格记录，同时记录真实时间原点和步长；不把音频 16 kHz 采样率当作标签采样率。
- 以人工审核的 N 秒录像段为审核单位，保存完整原录像时间轴上的标签及按类别的已审核范围；10 秒窗口切分放在后续训练预处理阶段。
- 请求导出范围、关键帧造成的实际范围和训练标签相互独立；重叠导出不重复生成同一来源的训练样本。
- 未审核区域不是负样本，模型预填不是人工真值。当前训练接口不支持未知位置的 mask，未来需选择完整审核窗口或实现带 mask 的训练链路。
- 同一来源录像的切片保持训练/验证/测试分组隔离，并补充随机区间、无枪声背景和误报样本，避免只依赖模型已发现的候选。

只用音频能否可靠判断本人开枪或命中仍待验证；预留事件类别和适配器不等于这些语义已实现。
