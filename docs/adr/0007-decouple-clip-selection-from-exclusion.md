# 选片勾选与人工排除决定解耦，取消全选按钮自身死锁

候选片段的导出选择（Checkbox 勾选）与人工排除决定（Exclude Decision）在领域模型和界面表现上彻底解耦。取消勾选仅代表该片段不作为“选片”纳入当前导出批次，该候选继续保留在时间轴与列表中可见；只有用户显式点击「排除」操作，才建立人工排除决定。

这一决定修复了旧实现中“取消勾选直接写入 exclude 决定，导致候选被物理过滤销毁，全不选清空全部内容并使全选按钮永久置灰死锁”的严重交互缺陷。

## 背景与问题

在 ADR 0004 确立“人工复核决定独立于自动候选保留”后，早期实现将列表勾选框（Checkbox）与工作区的人工决定状态混用：
1. 取消勾选时直接调用 `workspace.choose(id, false)`，写入了 `kind: 'exclude'` 的人工排除决定；
2. 数据层 `clipsFor(source)` 自动过滤掉所有匹配 `excluded` 的候选，界面在渲染循环中直接调用 `node.remove()` 销毁了 DOM；
3. 点击「全不选」时，全部候选被打上排除标记并瞬间清空，导致候选列表为空；
4. 界面依赖 `!saved.clips.some(...)` 判断批量按钮状态，使「全选」按钮在清空后瞬间被自身置灰（disabled），用户无法再通过点击全选恢复，产生单向死锁。

此外，「退出选片」等操作文案引发歧义，用户误以为是丢弃已剪辑片段，实际仅为时间轴全片视野重置。

## 决策

1. **选片勾选（Selection）与排除决定（Exclusion）解耦**：
   - 勾选状态（Checkbox）仅表达是否纳入即将提交的导出批次（即 [CONTEXT.md](../../CONTEXT.md) 定义的“选片”）；
   - 取消勾选不创建 `exclude` 人工决定，候选依然存在于时间轴与候选列表中，仅以弱化透明度显示；
   - 只有用户显式点击「排除」按钮（或快捷键 Delete），才创建明确的人工排除决定。
2. **列表与批量操作防呆**：
   - 「全不选」仅批量将未排除候选的勾选状态置为 `false`，绝不销毁任何候选，列表项全部保留；
   - 「全选」始终保持可用，点击后一键重新勾选所有非排除候选；彻底废除清空后禁用全选按钮的死锁逻辑；
   - 「显示已排除」复选框同时作用于时间轴与候选列表；已排除项在列表中保留占位（带删除线与弱化背景），右侧操作按钮由「排除」切换为「恢复」。
3. **交互澄清**：
   - 原片时间轴的「退出选片」更名为「全片视野」（仅恢复时间轴缩放跨度至整部录像，不改变任何片段的选中状态）；
   - 操作按钮上的外链箭头符号 `↗` 移除，与真正的外部链接区分。

## 取舍与影响

- **代价**：复核工作区状态需明确区分 `selected`（批次参与态）与 `decisions.exclude`（人工否定态），渲染层需同时呈现未选中态与已排除态，不再采用粗暴的空数组过滤。
- **一致性**：与 ADR 0004 保持兼容——人工明确排除的决定依然受独立持久保护；补充建议与人工裁边行为维持不变。
- **范围界定**：本 ADR 仅规范复核界面的选片勾选与排除语义；复杂的分析/导出细粒度互斥、录像生命周期移除与导出锁等调度机制暂不包含在内，留待后续专项决策。
