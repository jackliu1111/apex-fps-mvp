# 导出统一直接写入目录，以文件关闭成功作为保存边界

当前下载成片缓存会自动撤销尚未保存的成片链接，而普通下载链接无法向页面可靠报告文件是否保存成功。用户确认导出统一直接写入所选目录：首次选择目录，本页面后续批次沿用；关闭普通下载链接入口。不支持目录选择和直接写入的浏览器明确提示更换支持的浏览器，目录或权限不可用时等待重新选择，不自动回退到内存下载。

导出流式写盘并限制处理中缓冲。文件写入流成功关闭即视为保存完成；之后取消也保留该文件，只停止未完成的工作。未完成文件尝试清理；清理失败须同时报告原始错误、清理错误及遗留文件位置。保存后的附加检查状态与保存结果分开表达，不因取消附加检查删除已保存文件。

## 状态与范围

本决策已接受，**已在本地实现，尚未部署；macOS Chrome 原生目录选择、真实磁盘写入、取消与撤销授权后的恢复已验收，Edge、外接卷拔插仍未验收**。核查基线为 `636d177c7b062b5af68893acca54a54c2b7f628d`；基线中的视频下载链接和成片缓存淘汰路径现已移除。决策过程、问题分级和待讨论事项见[核查与决策记录](../review/main-audit-export-decisions-20261030.md)。

保留 ADR 0005 中提交即固定批次的原则。本决策不恢复跨刷新持久化，也不表示 ADR 0005 的历史自动保存描述仍是当前实现；当前复核状态仅保留于页面会话。

## 取舍

- 放弃普通下载链接的兼容性，换取明确的保存成功边界和统一的取消语义。
- 不采用点击下载后立即或延迟释放成片：点击和等待时长都不能证明保存成功。
- 不继续以自动淘汰未保存成片控制内存：正常流程不再持有等待下载的完整成片，内存预算用于处理中缓冲。
- 磁盘成片的任务记录和复用索引仍可保留；释放索引或处理资源不能等同于删除磁盘文件。
- 等待目录、排队、运行中的任务需要离页提醒；失败或取消的历史记录不应单独触发提醒。此项不取消对未提交人工选片的已有保护。

## 浏览器能力与运行条件

2026-10-30 查阅的兼容资料显示：桌面 Chrome、Edge 支持所需的目录选择能力，Safari、Firefox 尚不支持 `showDirectoryPicker()`。本项目建议使用桌面 Chrome/Edge；这不是已完成这两个浏览器的完整产品验收，也不是所有 Chromium 衍生浏览器必然可用的承诺。Android Chrome 也已有该 API 支持，不能写成“只有桌面支持”；移动端完整媒体导出不在本次验收范围。来源：[MDN 兼容数据源](https://github.com/mdn/browser-compat-data/blob/main/api/Window.json)、[Chrome 官方说明](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)。

目录选择须在安全上下文（部署使用 HTTPS，本机开发使用 localhost/回环地址）中由用户点击触发；后续重新弹出选择器同样需要有效的用户激活，不能等后台队列开始后自动弹出。实现须检测 `isSecureContext`、`showDirectoryPicker` 和实际写入授权，并处理权限拒绝；API 存在不代表媒体编码或目录授权一定可用。来源：[File System Access 规范](https://wicg.github.io/file-system-access/#api-showdirectorypicker)、[安全上下文规范](https://w3c.github.io/webappsec-secure-contexts/#is-origin-trustworthy)。


## 本地实现与验证（2026-10-30）

- 所有批次必须有输出目录；未取得目录或权限失效时等待用户点击重新选择。恢复只处理未完成片段，逐文件保留保存目录，后续默认目录不改写历史成果。
- 文件关闭成功为保存边界；关闭过程中取消等待结果。保存后编码收尾或媒体检查失败作为附加检查错误，取消不删除已保存文件。
- 编码/写入失败和清理失败同时报告，并保留遗留位置；重新选择目录、重试成功仍保留清理警告。
- 256 KiB 分块写盘，待写入编码数据队列上限 64 MiB；不再缓存完整成片 Blob。该限制不代表全进程内存上限。最多 128 项磁盘复用索引的释放不删除文件。
- 导出侧离页提醒仅看等待目录、排队、运行中，未提交人工选片仍独立保护。
- 按 TDD 在公开导出器、队列及浏览器操作边界逐项记录失败后修复。自动化浏览器测试使用真实 Chrome 编码与 OPFS 写入/读回，覆盖 4K60、29.97fps、可变帧率和真实录像片段；这一层测试替代原生目录选择器。
- 另在 macOS Chrome 中通过原生系统窗口选择目录，在用户可见磁盘目录写入 8 个 WebM；取消半成品完成清理，关闭阶段取消保留已保存文件。Chrome 实际撤销授权后，队列等待新目录；取消重新选择和拒绝新授权均保留等待状态，选择新目录后只恢复剩余片段，原成果哈希不变。正式产品页面另验证取消选目录、撤销授权与重新选择后保存两个 MP4。时序暂停仅在独立验收页中使用，权限、选择器和磁盘操作均为原生实现；外接卷拔插、操作系统 ACL 失效与 Edge 尚未验收。

可重跑的测试见 `model_web_ui/browser.prototype/tests/browser-export.test.mjs`、`export-queue.test.mjs`、`verify-directory-export.cjs`、`verify-directory-errors.cjs`、`verify-source-export.cjs`、`verify-session-lifecycle.cjs`。详细证据与重跑命令见[本地实现验证](../review/adr6-directory-export-validation-20261030.md)。历史核查记录保留原基线结论，不作为当前实现状态。
