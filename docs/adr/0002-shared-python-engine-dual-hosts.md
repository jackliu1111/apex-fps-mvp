# 共享 Python 推理引擎，提供 Electron 与 Python 两套服务入口

为同时满足 Windows/Mac 桌面分发和轻量内部测试，采用一个共享 Python 推理实现，由 Electron 桌面服务和 Python Web 服务分别承载。Electron 管理桌面窗口与推理子进程；Python Web 服务可独立运行，便于快速测试模型和查看中间结果，不依赖 Electron/Bun 运行时。两个入口复用模型适配、候选规则和结果契约，标注与训练仍按 [ADR 0001](0001-audio-model-first.md) 延后。

## 取舍与影响

- 此决策替代此前以 Bun 本地 Web 服务作为唯一承载方式的建议。现有 React 界面可复用，通过传输适配层连接 IPC 或 HTTP；Bun 相关运行时调用需要迁移。
- 建议把模型枪声流程组织为共享 Python 任务核心：推理引擎保持独立，后处理和媒体操作统一实现；入口仅负责请求适配与宿主生命周期。具体模块拆分和 HTTP 框架仍属于实施设计。
- 共享指实现与契约复用，不要求两个入口同时运行或共享模型内存。两个实例使用独立数据目录，或以目录锁防止并发写入。
- Python 测试入口保留受控环境启动方式，避免每次内部试验都要构建桌面包；“轻量”不意味着可以省略 PyTorch、权重或 FFmpeg。
- Electron 桌面入口采用独立 Python 运行目录随包分发。Windows/Mac 仍需分别处理原生依赖、签名与真实运行验收；桌面框架不提供跨操作系统通用的推理二进制。
- 两个入口必须通过同一组行为场景和代表性录屏验证，防止测试入口通过而桌面入口因参数、路径或版本差异失效。

完整职责、接口与分发方案见 [模型服务方案](../design/model-service.md)。
