# 以录像库、自动接入与纯音频实时分析取代独立实时伴随模式

[ADR 0008](0008-live-proxy-and-directory-conform.md) 让玩家在独立的实时页面里共享画面并看近期回看，但录像仍由 OBS、NVIDIA 等外部录屏软件保存。玩家在网页上看到画面后，容易误以为整局已经在录；Apex 通常全屏运行，局内切出回看的机会很少，浏览器在游戏占焦点时也收不到快捷键打点。玩家真正的痛点是录完以后立刻拿到整理好的交火片段，并在最少的浏览器操作下完成复核与导出。

因此决定：**产品主入口改为本地选片工作区的录像库，原「分析队列」更名为「录像库」。对局期间采用纯音频的对局监听进行实时分析（不再采集或保留游戏画面）；录像监听目录中出现新保存的原录像时自动接入录像库，并通过原片升格直接关联实时分析结果，而不是默认在停录后读取整片做离线分析。**

## 决策

1. **录像库是唯一主入口**
   - 原「分析队列」升级并更名为「录像库」，统一呈现手动加入和自动接入的原录像，以及各自的对齐、分析、复核和导出进度；新录像的接入与处理状态直接在录像库内实时显示，不另开页面。
   - 移除左上角的工作区模式切换和独立的实时伴随页面。复核工作台和导出任务页面保持不变。
   - > 已被 [ADR 0010](0010-split-library-review-workspace.md) 部分取代：录像库与片段复核合并为左右分栏的本地选片工作区，对局监听与录像监听目录移入全局顶栏；导出任务页面仍保持不变。

2. **以纯音频实时分析为主路径，自动接入后直接升格**
   - 对局期间通过「对局监听」实时采集游戏声音并计算枪声预测分数；不采集、不显示也不保留游戏画面。
   - 录像监听目录中出现新的原录像且确认写入完成时，自动接入录像库：
     - 与对局监听时间有重叠的录像，直接执行原片升格，把已算好的枪声预测和波形对齐到原录像，停录后立即可复核，不再读取整片重跑离线分析；
     - 未被对局监听覆盖的新录像，同样自动加入录像库并标注「未分析」，由用户按需手动发起离线分析，避免玩家进入下一局时后台重型离线扫描与游戏争抢 CPU；
     - 粗略对齐的录像在录像库与复核页明确标注，并提供「重新离线分析」入口。

3. **移除实时伴随代理与局内手动打点**
   - 移除浏览器画面采集、近期回看缓存、省电胶片档和局内回看进度条。浏览器既不显示也不保留游戏画面，避免让玩家误以为正在录像，并省去视频编码开销。
   - 移除对局监听期间的手动打点与实时预决策。所有保留、排除与裁边等人工复核决定统一在原片接入后的复核工作台内完成。

4. **浏览器内操作最少**
   - 开录、停录由外部录屏软件完成，本决定范围内产品不尝试控制录制。
   - 首次使用：授予录像监听目录与输出目录权限。之后打开页面：目录授权仍然有效时自动恢复目录监听；开启对局监听时在录像库顶栏一键启动（纯网页下若使用系统音频，浏览器仍会弹出一次共享选择，拿到音轨后立即停用视频轨；使用虚拟声卡则可复用设备权限）。
   - 新录像就绪时，通过标签页标题、图标角标和可选的系统通知提示，不抢焦点，也不自动跳转。
   - 玩家切回页面时，默认打开最新就绪的录像，并定位到首个/高分候选。复核和导出仍需玩家确认，与 [ADR 0005](0005-fixed-export-batches-and-saved-review.md)、[ADR 0006](0006-directory-only-export.md) 一致。

5. **沿用 ADR 0008 的部分**
   - 录像监听目录只读，并与输出目录隔离；过滤本会话导出的成片；按稳定落盘判定文件是否写完；两阶段对齐（墙钟粗对齐 + 局部声纹包络互相关精对齐）与三级透明降级；通过 `importPrecomputed` 接入复核和导出流程；播放原片时的回环防自激门控。

## 被拒绝的替代方案

- **保留短时回看作为默认功能**：局内很少有机会使用，还会让玩家误以为网页在录像，并持续占用编码资源和内存。
- **默认停录后读取整片做离线分析**：长录像停录后需要等待文件扫描与全片推理，且在玩家连续开下一局时容易与游戏争抢 CPU；纯音频实时分析可做到停录即就绪。
- **浏览器直接录完整局**：几乎所有 Windows 玩家都已有免费录屏工具；长时间录制的画质、游戏帧率、音画同步和大文件保存问题投入大、收益小。

## 暂不纳入本决定

以下事项暂不决定，后续按需另行决策：安装为应用并在登录时启动、连接 OBS 控制录制或获取文件路径、画中画小窗、本地助手、按局切分长录像。

## 待验证

1. 目录授权保留后，页面打开时能否不经点击恢复读取并开始目录监听；如果做不到，以「一次点击恢复」作为底线。
2. 页面在后台时，目录检查会不会被浏览器限速，导致发现新录像变慢。
3. 停录后文件写完、发现并完成局部声纹对齐的真实耗时（分 OBS MKV 与 NVIDIA MP4 验证）。

## 影响

- 实时伴随页面、模式切换和代理缓冲相关代码（如 `site/live-companion-ui.mjs`、`site/live-proxy-buffer.mjs`）在实现本决定时移除或拆分；纯音频对局监听控制、目录监听、对齐和升格逻辑迁入本地选片工作区的录像库。
- [实时伴随分析设计方案](../design/live-companion-analysis.md) 中与代理画面、独立工作区相关的部分不再适用。
