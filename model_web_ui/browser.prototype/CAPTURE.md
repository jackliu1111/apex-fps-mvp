# 纯网页原型的验证记录

日期：2026-10-26。原型分支：`codex/prototype-browser-local`，基于 `2ac7c6f`。

问题：现有 BEATs 模型能否在纯网页里，与本地媒体读取、音轨选择、复核和导出连成可操作的流程？

结论：**短合成样本的真实链路已在 macOS Chrome 跑通**。页面未调用 Python 推理、系统 FFmpeg 或本地媒体服务。Python 只在开发阶段生成 ONNX 和提供静态文件；本机 FFmpeg 仅用于对浏览器已下载的成片进行独立检查。本轮没有评价长录像性能、Apex 识别质量或确定生产架构。

## 已观察的证据

- ONNX 固定输入 `[1,160000]`、输出 `[1,250,447]`。合成噪声与原 PyTorch 分数相比，Python ONNX Runtime 最大绝对误差 `7.82310962677002e-7`。
- Chrome 内点击基准校验：111,750 个分数，最大绝对误差 `7.674098014831543e-7`，通过 `1e-3` 阈值。这是单个合成输入的数值对照。
- 浏览器内部生成双音轨 WebM；原型显示两条独立音轨，未选择时禁止分析。音轨一是合成脉冲，音轨二是 440 Hz 正弦音。
- 分别选轨分析成功：12 秒音频产生 2 个重叠窗口、300 帧分数。默认 0.2 阈值无枪声候选，未伪造识别结果。阈值置零后可重算出覆盖全段的候选，再恢复 0.2 并使用手动范围验证导出。
- 第一音轨手动范围 `1.2–4.8 s` 生成了可播放预览；下载文件 `browser-synthetic-01.webm` 为 171,351 字节，VP8 640×360 + 单条 Opus 音轨，容器时长 3.633 秒，FFmpeg 完整解码成功。
- 修订版为合成视频补充 12 fps 轨道元数据，源视频读回为约 12 秒。第二音轨手动范围 `0–5 s` 下载文件 `browser-synthetic-track2-01.webm` 为 214,665 字节，VP8 640×360 + 单条 Opus 音轨，ffprobe 容器时长 5.000 秒，完整解码成功。解码音频的前 1 秒 FFT 峰值为 440 Hz，符合所选音轨。
- 已观察取消状态：0 完成窗口、0 分数帧、无候选；重新分析后 2 窗口／300 帧完成。失败或取消不会伪装为完成。
- 切换音轨后旧分数和候选清空；修订版同时清空旧预览。已下载链接保留并在新导出文件名中标明音轨序号。
- 使用 Chrome 原生文件选择器重新导入第二音轨成片成功，作为另一份录像加入队列并要求重新确认音轨。
- 通过实际页面截图检查了预览、范围编辑、下载链接和操作导览布局。没有增加自动化测试套件；JavaScript 语法、Python 语法和源码空白检查通过。

## 尚未证明的内容

- Mediabunny 1.25.0 对部分 WebM 尾帧时长的读回与容器时长有差异：上面的 5 秒成片浏览器总时长读回约 4.98 秒，视频轨读回约 4.92 秒。界面使用“读回约”标注，不声称逐帧精确。正式版本需要单独解决尾帧和容器时长契约。
- 浏览器音频解码、重采样、混音与 FFmpeg 的全链路精度尚未对照；合成输入模型校验不能覆盖这一点。
- 未分析真实 Apex 录像；未验证长录像、多文件完整批处理、所有格式、负起点轨道、人工感知同步、后台运行与刷新恢复。
- 导出是最高 720p WebM 重编码，且成片保留在内存。不是原清晰度无损导出，也不是批量生产方案。
- 模型仍是通用 AudioSet Strong 识别，不代表枪声来自本人、命中或击杀。

## 2026-10-26 模型加载问题跟进

用户报告停在模型导入阶段。检查时两个现有 Chrome 标签页都已空闲，因此未捕获用户当时的活动任务。可重现的环境故障是静态预览服务不再监听 8792：`curl --noproxy '*' --fail --max-time 15 -sS -o /dev/null -w '%{http_code} %{size_download}\n' http://127.0.0.1:8792/assets/beats.onnx` 返回连接拒绝／HTTP 000。使用默认代理时则返回 502。模型文件本身仍为 373,403,807 字节。

恢复独立后台静态服务后，同一直接请求返回 HTTP 200、373,403,807 字节。新增 `--background` 启动方式，避免预览进程依赖执行会话；将 Worker 模型读取和引擎初始化拆开显示，并加入字节进度、HTTP 错误、完整长度校验和 30 秒无数据超时。计算阶段不设该超时。

Chrome 再次执行真实基准成功：日志显示 17:41:21 读完 356.1 MiB 并开始初始化，17:41:22 进入窗口计算，17:41:23 完成，最大分数误差仍为 `7.674098014831543e-7`。这证明当前加载链路已恢复；无法倒推用户当时是否还遇到其他问题。原型未新增测试套件，使用上述 HTTP 命令与真实页面基准作为复现／回归入口。
